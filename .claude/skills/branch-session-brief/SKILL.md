# 분기 세션 지시서 틀 (photo-video-manager)

메인이 `start_session` 을 부르기 전에 이 틀로 `prompt` 를 만든다. 규칙 원본은 `CLAUDE.md` 4절 · 7절이고, 이 파일은 그 실행 틀이다 (2026-11-13 원인 `docs/decisions/2026-11-13-parallel-wait-cause.md`).

## 시작하기 전 (메인)
1. 같은 파일을 만지는 작업은 한 세션으로 묶는다 (예: `scripts/check*.js` 두 항목).
2. 같은 PC 에서 `npm run check` 를 도는 세션은 **2개 이하**. 점검 포트 자동 선택 · 임시 폴더 분리(나중에 할 일)가 머지되기 전까지는 특히 지킨다.
3. 사용자 결정이 필요한 작업(새 기능 설계)은 분기하지 않는다.
4. 모델: S · M 분기는 `start_session` 의 `model` 을 `sonnet`, L 은 `opus` 로 직접 적음 (비우면 메인 모델을 따라가서 메인이 Sonnet 일 때 어긋남). 같은 원인으로 2번 막히면 Opus 로 다시 시작 (`CLAUDE.md` 7절 토큰 규칙)
5. 시작 직후 사용자에게 "세션 이름 · 등급 · 완료 예상"을 한 줄로 알리고, 20~30분 안에 세션 노트도 PR 도 없으면 `list_sessions` 로 확인해 `SendMessage` 로 깨운다.

## prompt 에 반드시 넣을 것
- 목표 1개 · 등급 · 건드릴 파일 · 건드리면 안 되는 파일 (다른 분기가 만지는 것)
- 시작: `git fetch` 하고 origin/main 최신 위에서 브랜치 생성
- **PR 먼저**: 코드가 되면 점검을 기다리기 전에 draft PR 로 먼저 올린다. 30분 안에 PR 이 없으면 현재 상태라도 draft 로 올린다
- **점검**: 바꾼 부분의 점검을 먼저 돌리고, 전체 `npm run check` 는 커밋 전 한 번만. 18 · 43c · 48c 는 원래 불안정 항목이라 한 번 실패하면 한 번 재실행하고, 그래도 실패하면 수정 전 main 과 비교하지 말고 PR 본문에 적은 뒤 CI 를 최종 판정으로 삼는다
- **기다리는 일**(점검 · 검증 에이전트 · CI): 턴을 끝내지 않는다. 점검은 앞에서 돌리거나 `Monitor` 의 until 루프로 끝날 때까지 기다린다. 못 기다리는 사정이 있으면 "막힌 이유" 한 줄을 바로 보고한다 ("기다리는 중" 만 말하고 끝내기 금지)
- 보고는 **끝났을 때 · 막혔을 때 · PR 이 만들어졌을 때만**, 첫 줄에 `PR #번호 | 등급 | CI | 검증 댓글 | 앱 확인 댓글 | 머지 여부` 를 적는다
- L 등급(경로는 `CLAUDE.md` 4절)이면 PR 까지만 만들고 멈춘다. 머지는 메인이 한다
- 범위 밖 발견은 `PROGRESS.md` 나중에 할 일에만 적고 손대지 않는다. 새 세션을 만들지 않는다
- `PROGRESS.md` · `PROGRESS-LOG.md` 충돌은 양쪽 줄을 모두 남긴다. 작업 기록은 같은 PR 안에서, 결과 칸에 검증 판정을 직접 적는다
- 임시 프로세스(앱 · exiftool)는 끝나면 종료한다. 다른 세션의 폴더 · 프로세스는 건드리지 않는다

## 세션이 끝나면 (메인)
- 노트는 세션의 보고일 뿐이다. `gh pr view`(CI · 충돌 · 마지막 커밋)와 PR 댓글(검증 · 앱 확인)을 직접 확인한 뒤 `--match-head-commit` 으로 머지한다
- 노트에 "기다리는 중" · "곧 이어서" 만 있으면 끝난 것이 아니다 → `SendMessage` 로 "PR 이 없다 · 무엇이 막혔나" 를 묻는다
- 머지 뒤 충돌이 나면(문서 충돌이 가장 흔함) 해당 세션에 "origin/main 병합, 양쪽 줄 유지, 문서만이면 점검 생략" 을 보낸다
