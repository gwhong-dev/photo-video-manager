# 2026-11-24 비슷한 사진: 묶음 전체 버리기 허용 + "이 묶음 N장 모두 버리기" 버튼

## 문제
- 사용자: "같은 묶음에서 모두 안 남기고 싶기도 한데, 무조건 1개 이상 남겨야 하는 점도 이상하고, '비슷한 1묶음'을 바로 전체 삭제할 수 있는 버튼도 없어"
- 예전 규칙(#34): 묶음마다 한 장은 꼭 남김. 화면은 마지막 남김을 버림으로 바꾸지 못하게 막았고, main 도 한 장도 안 남는 묶음이면 거절했어요
- 그래서 비슷하지만 모두 필요 없는 사진(흔들린 연속 사진 등)은 한 장씩 남긴 뒤 갤러리에서 따로 지워야 했어요

## 고른 방식
- **사용자가 직접 고른 경우에만** 묶음 전체를 버릴 수 있어요
  - 화면 표시 값: 사용자가 누른 `keep` · `discard`, 처음 자동 표시 `auto-keep` · `auto-discard`
  - 묶음의 모든 사진이 정확히 `discard`(사용자가 고름)일 때만 전체 버리기. 처음 자동 표시만으로는 한 장도 안 남는 일이 없어요
- 묶음 아래에 "이 묶음 N장 모두 버리기" 버튼: 묶음 사진을 모두 버림으로 바꾸고 바로 확인 창을 띄워요 (확인 창에 "그중 묶음 1개는 한 장도 남기지 않아요" 줄)
  - 확인 창에서 그만두면 버림 표시는 남아 있어 한 장씩 다시 남김으로 바꿀 수 있어요
- 화면은 전체 버리기로 고른 묶음의 번호를 `whole` 로 따로 보내고, main(`lib/similar-discard.js` checkDiscard)은 DB 로 묶음을 다시 만든 뒤
  - 한 장도 안 남는 묶음은 그 사진이 **모두 `whole` 안에 있을 때만** 허용, 아니면 "묶음이 바뀌어 남길 사진이 없어졌어요" 로 거절
  - → 화면을 연 뒤 묶음이 바뀌어(새 사진 추가 · 지문 다시 계산) 의도치 않게 한 장도 안 남는 경우는 예전처럼 막아요
- 옮기는 곳은 그대로 휴지통(없는 드라이브는 `_정리완료원본`), 영구 삭제 없음, 예정 줄을 먼저 적는 로그 그대로

## 버린 안
- 한 장 남김 규칙을 그냥 없애기: 묶음이 바뀌었을 때(사진 추가 · 다시 계산) 남길 사진이 사라지는 것을 main 이 못 막아요
- 확인 창 없이 버튼 하나로 바로 옮기기: "삭제 · 이동은 미리보기 뒤 실행" 규칙(CLAUDE.md 5절)에 어긋나요
- 자동 표시까지 전체 버리기로 보기: 사용자가 보지 않은 묶음이 통째로 사라질 수 있어요
