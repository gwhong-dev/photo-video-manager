# 개발 과정 토큰 줄이기 (2026-11-23)

## 왜
사용자: "대단한 걸 만드는 게 아니라 내가 쓰는 걸 만드는 건데, Max 요금제로도 토큰이 감당이 안 된다." 규칙이 제품 수준이라 혼자 쓰는 도구에는 과하다는 판단.

## 무엇을 쟀나
2026-11-12 ~ 11-23 이 프로젝트의 대화 기록 88개(메인 세션 34 · 에이전트 54, 턴 4,756개)를 집계. 토큰은 API 요금 비율(캐시 읽기 0.1 · 캐시 쓰기 1.25 · 출력 5 · 입력 1)로 가중해 비교했다 (요금제 한도 계산과 정확히 같지는 않은 어림값).

| 어디서 | 몫 |
|---|---|
| 캐시 읽기 = 말할 때마다 대화 전체를 다시 읽는 값 | **73%** |
| 캐시 쓰기 (새로 올린 내용 · 쉬었다 돌아와 다시 올림) | 16% (그중 10만 넘게 통째로 다시 올린 18번이 5%) |
| 출력 (Claude 가 쓴 글 · 코드) | 12% |
| 대화가 20만 토큰을 넘은 턴에서 나온 비용 | **68%** |
| 가장 긴 메인 세션 3개 (메시지 400~684개, 대화 70만~87만 토큰) | **48%** |
| 에이전트(검증 · 조사) 전체 | 11% |
| 세션 시작 바탕(기본 설명 · 도구 · 연결 도구 · 플러그인 · 규칙) 약 9만 토큰을 턴마다 다시 읽는 값 | 약 25% |

대화에 들어간 도구 결과는 파일 읽기가 가장 많았다 (cat · sed · grep 330만 자 + Read 180만 자, `cleaner.js` 33번 · `planner.js` 22번). `npm run check` 출력은 62만 자, 한국어 훅이 다시 쓰게 한 일은 40번(1% 미만)으로 작았다.

## 고른 처방 (어림 절감)
1. **대화 길이 상한 20만 토큰** (약 40%): `.claude/settings.json` 에 `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200000` (공식 문서 env-vars · model-config 의 자동 요약 창 크기). 주제가 바뀌면 새 세션, 메인은 15만 토큰을 넘으면 하던 PR 끝에 교체
2. **시작 바탕 줄이기** (약 10%): 이 프로젝트에서 superpowers · context7 플러그인을 끔. 계정 연결 도구(Canva · Figma · Notion · Google Drive)는 사용자가 앱에서 끔
3. **큰 파일 부분 읽기** (약 5%): `grep -n` 으로 줄을 찾고 그 범위만, diff 는 `--stat` 먼저, 같은 범위 다시 읽기 금지
4. **M 검증은 바뀐 줄만 + Sonnet, 분기 S · M 은 Sonnet** (약 5%): L 은 전체 검증 그대로

합쳐서 대략 절반 이상 줄어들 것으로 본다 (항목끼리 겹쳐서 단순 합은 아님).

## 그대로 둔 것 (안전)
L 등급 전체 검증 · 앱 실행 확인 · 사용자 "머지" 승인, 원본 · 삭제 안전 규칙, 한국어 훅, typescript-lsp(코드를 고친 직후 문법 오류를 잡는 값이 있음).

## 버린 안
- **점검 출력 줄이기 · CLAUDE.md 줄이기**: 처음엔 "효과 큼"으로 짐작했지만 실제 집계에서 각각 1~2% 정도라 이번에는 하지 않음
- **M 검증 아예 빼기**: 에이전트 전체가 11% 라 아끼는 양이 작고, 실제로 잡은 버그가 있었음(#122 장수 불일치 · #133 창 겹침). 대신 바뀐 줄만 보게 해 비용을 줄임
- **분기 세션 금지(전부 차례대로)**: 짧은 세션(메시지 50개 미만)은 11개 합쳐 4% 뿐. 비싼 건 병렬이 아니라 오래 이어 쓴 메인이라 병렬 규칙은 그대로
  - → 2026-11-24 바뀜: 비용이 아니라 "갈래가 많아 헷갈림" 때문에 기본을 한 줄기로, 분기는 사용자 요청 때만 (`docs/decisions/2026-11-24-one-line-sessions.md`)
- **작업 기록 짧게 · 트리 등록 줄이기**: Docs 도구 결과가 합쳐 약 28만 자로 작고, 포트폴리오 재료가 줄어드는 단점이 커서 그대로
