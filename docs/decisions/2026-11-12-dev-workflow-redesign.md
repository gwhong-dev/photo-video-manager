## 2. 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 규칙 원본 | 저장소 `CLAUDE.md` 하나. 다른 곳과 다르면 CLAUDE.md 우선 | 두 PC · 모든 세션이 같은 파일을 읽음 |
| 코드 대화 | 초안(Plan 모드) → 구현 → 머지까지 **Code 탭 한 곳** | 실제 코드를 보며 계획 → 중계 없음 |
| 채팅 역할 | 노션 · 포트폴리오 · 자기소개서만. 저장소 파일을 읽어 정리 | 코드로 넘길 것이 생기지 않음 |
| 작업 기록 | `PROGRESS-LOG.md` "🧾 작업 기록" 표에 작업당 1줄(문제 · 해결 · 결과) + 결정은 `docs/decisions/` + 고른 캡처는 `docs/images/` | 채팅이 저장소 파일만으로 정리 가능 |
| 작업 PC | PC A 집 게이밍 노트북(기준) · PC B 삼성 노트북(밖). 둘 다 로컬 Code, **각 PC 내장 디스크에 clone**, git 으로만 이어감. 시작 = fetch · 미커밋 · 미push 확인, 끝 = commit + push | 로컬이라 앱 화면 · 휴지통 · 드라이브 확인까지 Claude 가 직접 |
| 절대 경로 | 문서 · 스크립트에 쓰지 않음 | 프로젝트 위치가 PC 마다 다름 |
| 사진 · 영상 자료 | 외장 SSD/USB 에만 (저장소 · 작업 폴더에 넣지 않음) | 개인 사진 · 위치 정보, 용량 |
| 등급 | S · M · L 을 **바꾸는 파일 경로로 기계적으로** 판정 (CLAUDE.md · `.claude/**` · `.github/**` · 원본 정리 · 이동 · DB · 의존성 · 배포 파일 = L) | 등급을 코드를 쓴 에이전트가 판단하지 않게 |
| 검증 | M · L 은 PR 마다 처음 보는 검증 에이전트 1회, 지적은 같은 PR 에서 고침 | "수정 단계"에 몰면 검증 전 변경이 main 에 쌓임 |
| 머지 | S · M = CI(+검증) 뒤 Claude, **L = 사용자 "머지" 승인 뒤**. 라벨 자동 머지는 쓰지 않음 | 원본 정리 · DB · 배포는 되돌리기 어려움, main 브랜치 보호가 없음 |
| 분기 세션 | 클라우드 + Remote Control 중계 대신 로컬 `start_session` 분기 | PC 확인이 필요한 일이 많은 프로그램 |

## 3. 버린 안

- **개발 단계 / 수정 단계 분리 유지**: 검증을 나중에 몰아서 하면 L 변경이 검증 없이 main 에 들어감 → PR 마다 검증으로 바꿈. 사람 확인 · 질문을 모아 두는 것만 남김
- **클라우드 세션에서 작업 + PC 로 갈래 띄우기**: 앱 화면 · 휴지통 확인을 못 해 결국 중계가 생김
- **USB 를 작업 폴더로 계속 쓰기**: 드라이브 문자 차이 · `.git` 손상 위험
- **`auto-merge.yml` 라벨 머지**: L 판정 목록이 CLAUDE.md 와 따로 놀고(예: CLAUDE.md 가 빠져 있음), 사용자 승인 단계를 건너뜀 → 쓰지 않음 (파일은 남겨 둠, 지우는 건 사용자 결정)
