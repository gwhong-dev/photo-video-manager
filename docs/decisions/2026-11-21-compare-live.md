# 비슷한 사진 크게 비교 + 라이브 포토 재생 (2026-11-21)

## 문제
- 비슷한 사진 화면은 칸이 작고(최소 140px) 그림도 썸네일(긴 변 320px)이라, 초점 · 흔들림 · 눈 감음을 보고 고를 수 없었어요. 오른쪽 패널도 1200px 미리보기까지만 보여요.
- "Live Photo" 태그가 붙은 사진이 움직이지 않았어요. 앱에 영상 재생 기능이 없었어요.

## 확인한 것
- 실사용 사진(2026-11-17, `2026-11-17_184927.jpg`)은 아이폰식 "사진 + 따로 된 영상" 짝이 아니었어요. **JPG 끝에 H.264 영상(약 3초)이 붙은 모션 포토**였고, 사진 안 XMP 에 `MicroVideoOffset`(끝에서 몇 바이트가 영상인지)이 적혀 있었어요. 가져올 때의 원본도 JPG 하나뿐이었어요.
- 그날 사진 69장 중 4장이 모션 포토였어요.
- H.264 는 앱의 화면(Chromium)이 바로 재생해요. 걱정하던 HEVC 문제는 이 사진에는 해당되지 않았어요.

## 고른 방식
### 비교 창 (사용자가 정한 동작)
- 사진 더블클릭, 사진을 고른 뒤 Space, 묶음의 "크게 보며 고르기"로 열어요.
- 처음에는 한 장을 크게: ←/→ 로 넘겨 봐요.
- 가장 좋은 사진에서 **Space → 왼쪽에 고정(남김)**. 아직 아무것도 안 고른 묶음이면 원래 추천은 버림으로 바꿔요.
- 오른쪽에서 나머지를 ←/→ 로 넘기며 **↑ = 버림, ↓ = 남김**(정하면 다음 사진으로). 오른쪽에서 Space 를 다시 누르면 고정을 바꿔요.
- 휠 = 마우스 자리 확대, 끌기 = 옮기기, 더블클릭 = 맞춤 ↔ 원본 크기. **두 칸이 같은 자리 · 같은 배율로 같이 움직여요.** 크기가 다른 사진도 비율로 맞춰요.
- 원본 사진을 그대로 그려요(`pvm://original/<id>`). 화면이 못 그리는 형식(HEIC 등)은 1200px 미리보기로 대신해요.
- 표시는 비슷한 사진 화면과 같은 값이에요. 실제로 옮기는 건 지금처럼 화면 아래 확인 창에서만 해요. 마지막 남김은 버리지 못하는 규칙도 그대로예요.

### 라이브 포토 재생
- `pvm://live/<사진 번호>`: 같은 이름의 짝 영상(기존 `lib/live-pair.js` 규칙)이 먼저고, 없으면 JPG 끝에 붙은 영상(`lib/motion-photo.js`)을 써요. 둘 다 없으면 404 → 버튼을 안 보여요.
- 모션 포토는 XMP 두 가지 적는 법을 읽어요: 1판 `MicroVideoOffset`, 2판 `Item:Semantic="MotionPhoto"` 의 `Item:Length`. 찾은 자리가 영상 머리(`ftyp`)일 때만 믿어요. 사진 파일은 읽기만 해요.
- 오른쪽 패널과 비교 창에 "▶ 움직이는 사진" 버튼이 있고, 누르고 있는 동안 재생해요.
- 화면 보안 설정에 `media-src 'self' pvm:`(인터넷 주소 없음)를, pvm 주소에 `stream` 권한(영상 재생용)을 더했어요.

## 버린 안
- **칸 크기 조절 막대만**: 금방 되지만 두 사진을 같은 자리로 맞대어 볼 수 없어요.
- **처음부터 두 칸(왼쪽 = 추천 고정)**: 사용자가 "넘겨 보다가 Space 로 고정"하는 흐름을 골랐어요.
- **모션 포토 영상을 가져올 때 따로 꺼내 저장**: 사진 파일 · 가져오기 규칙을 바꾸는 큰 일이라, 재생할 때만 잘라 읽어요.
- **영상 있는지 미리 알려 주는 새 IPC**: `preload.js`(L)를 바꿔야 해요. 대신 `<video preload="metadata">` 로 주소를 열어 보고 404 면 버튼을 숨겨요.
