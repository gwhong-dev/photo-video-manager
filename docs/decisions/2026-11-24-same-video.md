# 비슷한 사진 화면의 "같은 영상" 묶음 (2026-11-24)

## 문제
- #141 전에는 이름만 다른 같은 영상(`IMG_0001(1).MOV` · 다른 폴더의 같은 영상)을 분류하면 백업 폴더에 MP4 가 2개씩(`IMG_0001.MP4` · `IMG_0001_1.MP4`) 저장됐다
- #141 로 앞으로는 안 생기지만, 이미 저장된 2개짜리는 그대로 남아 있다. 사용자 요청: 비슷한 사진 화면에서 이것도 정리하고 싶다

## 정한 것
- **묶는 조건 (모두 맞아야)**: 같은 날짜 폴더 · 같은 확장자 · 같은 가로 × 세로 · 크기 차이 5% 이내(남길 영상 기준) · 화면 데이터 지문(`videoStreamHash`, #141) 같음
  - 같은 확장자 조건을 더 붙임: MOV 를 MP4 로 포장만 바꾼 것도 화면 데이터 지문이 같아서, 확장자가 다른 짝까지 묶으면 원본 포장(MOV)을 버리게 될 수 있음
  - 지문은 위의 앞 조건(폴더 · 확장자 · 크기 · 가로 × 세로)으로 후보가 된 영상만 계산하고 DB(`video_hashes`, 경로 · 크기 · 수정 시각이 같을 때만 다시 씀)에 저장. 앱이 다른 일을 하면 멈춤
- **남길 것** = 꼬리 없는 이름 (이름이 짧은 쪽 → 가나다순). `IMG_0001.MP4` 를 남기고 `IMG_0001_1.MP4` · `IMG_0001(1).MP4` 를 옮김
- **옮기기**: 미리보기(확인 창) → 옮기기 직전 두 영상의 지문을 다시 계산해 목록과 같을 때만 → 휴지통(없는 드라이브는 `_정리완료원본`) → 로그 `same-video_*.txt`, 정리 기록 화면에 "같은 영상 정리". 영구 삭제 없음
- 남김 · 버림 표시는 고정 (사진 묶음처럼 바꾸지 않음). 묶음 전체 / 묶음 하나씩 옮기기

## 버린 안
- 이름만 보고 묶기 (`_1` 꼬리): 이름이 같은 다른 영상이 있을 수 있어 내용 확인 없이는 위험
- 파일 전체 지문(sha256): 같은 영상이라도 포장(메타데이터)이 다르면 달라서 못 찾음
- 사진 비슷함 비교(AI · 해시)에 섞기: 영상은 프레임 비교가 무겁고, 같은 영상은 "비슷함"이 아니라 "같음"이라 따로 보여 주는 게 판단이 쉬움
