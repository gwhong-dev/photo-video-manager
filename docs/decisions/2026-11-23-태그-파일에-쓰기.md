# 태그를 사진 · 영상 파일에 쓰기 (2026-11-23)

## 왜
- 내가 붙인 태그는 지금 `%APPDATA%\photo-video-manager` 의 `library.db`(`manual_tags` 표)와 기록 파일 `manual-edits.jsonl` 에만 있다 (2026-11-04 결정 "사진 파일에는 쓰지 않음", `lib/manual-tags.js` 주석).
- 그래서 다른 PC 에서 백업 폴더를 열면 내 태그가 하나도 없다. 앨범 태그(PhotoSync 가 파일 XMP `dc:subject` 에 써 둔 앨범 이름)만 보인다.
- 사용자: 여러 PC 에서 쓰는 것도 이 프로그램의 목적이다. **사진 태그는 실제 파일의 태그로 들어가야 하고, 프로그램 안에서만 남는 태그는 의미가 없다.**
- 이 결정으로 2026-11-04 의 "파일에 쓰지 않음"을 바꾼다. 원본(백업 폴더 파일)을 고치는 기능이라 구현은 L.
- 범위: 태그만. 설정 · DB 를 다른 PC 로 옮기는 문제, 직접 넣은 날짜 · 위치는 다루지 않는다 (`PROGRESS.md` 나중에 할 일).

## 정한 것 (사용자 선택)
| 질문 | 고른 것 | 버린 안 · 이유 |
|---|---|---|
| 태그를 어디에 | **A. 파일 안에 쓰기.** 쓸 수 없는 형식(BMP · AVI · MKV · WMV)은 이 PC 의 DB 에만 두고 ⚠️ 로 표시 | B. 옆에 `.xmp` 사이드카 파일: 원본은 안 건드리지만 탐색기가 못 읽고, 파일을 옮길 때 `.xmp` 를 따로 챙겨야 함. C. 파일 안 + 못 쓰는 형식만 `.xmp`: 휴지통 · 원본 정리 · 돌리기에서 `.xmp` 를 같이 옮기는 코드가 늘어나는데 대상 형식이 드묾 |
| 앨범 태그와 내 태그 | **하나로 합치기.** 파일에 있는 태그는 모두 같은 "태그"이고 이름 바꾸기 · 지우기 가능. 탐색기에서 단 태그도 똑같이 들어옴 | 구별 유지(파일에 "내 태그" 표시를 따로 적음): 앨범 태그를 읽기 전용으로 둔 까닭(파일에 못 씀)이 없어지고, 탐색기에서 단 태그가 읽기 전용으로 보이는 이상한 경우가 생김 |
| 언제 파일에 쓰나 | **모아서 쓰기.** 붙이기 · 떼기는 지금처럼 DB 에 먼저 두고, "N장 파일에 태그 쓰기"로 한 번에 씀. **프로그램을 닫을 때 파일에 안 쓴 태그가 있으면 "파일에 쓰지 않은 태그가 N장에 있어요. 지금 쓸까요?"로 알림** | 바로 쓰기: 붙일 때마다 파일을 다시 써서, 큰 영상이 섞이면 저장이 몇 분씩 걸림 |

## 확인한 것 (2026-11-23, 이 PC, exiftool 13.64, `test/samples/auto` 복사본, 한글 태그 "가족" · "여행 2026")
| 형식 | 파일 안에 쓰기 | 탐색기 "태그" 칸 | 내용 |
|---|---|---|---|
| JPG | ✅ XMP `dc:subject` | ✅ (XMP 만 써도 보임) | 픽셀 차이 0 (ImageMagick compare) |
| PNG · WEBP | ✅ XMP `dc:subject` | ✅ | 그대로 |
| MP4 · MOV | ✅ XMP `dc:subject` | XMP 만 쓰면 ❌ → Windows 용 칸 `Microsoft:Category` 도 쓰면 ✅ | ffmpeg 로 끝까지 재생 확인 OK |
| GIF | ✅ | ❌ | 그대로 |
| BMP · AVI · MKV | ❌ exiftool 이 쓰기를 지원하지 않음 | — | — |
| HEIC | 샘플이 없어 시험 못 함 (exiftool 은 쓰기 지원). 백업 폴더에서는 JPG 로 바꿔서 드묾 | | |

시험에서 찾은 주의할 점
1. **파일 지문(SHA1)이 바뀐다.** 지금 코드에서 두 곳이 이 지문에 기댄다.
   - 원본 정리 확인(`lib/cleaner.js` `trustedSig` · 지문 확인): 백업 파일이 쓸 때 기록과 달라져 원본이 "남김"이 된다
   - 다시 가져올 때 중복 판단(`lib/planner.js` ② `sameBytes`): 같은 사진을 또 가져오면 "이미 있음"이 아니라 `_1` 로 하나 더 저장된다 (애플 ID 가 없는 PNG 스크린샷 등)
   - 해결: exiftool `ImageDataHash`(태그 · 정보를 뺀 그림 · 영상 내용만의 지문, `-api ImageHashType=SHA256`)는 태그를 쓴 뒤에도 **JPG · PNG · WEBP · MP4 · MOV 모두 쓰기 전과 같았다.** 두 판단에서 바이트 지문이 다르면 내용 지문으로 한 번 더 비교한다
2. **태그를 쓸 때 목록 전체를 다시 적는다.** `-XMP-dc:Subject=가족` 처럼 쓰면 원래 있던 앨범 태그와 "비디오" 같은 종류 태그가 지워지는 걸 시험에서 봤다. 종류 태그(사진 · 비디오 · 스크린샷)는 늘 그대로 남긴다
3. **영상은 태그를 한 번 쓸 때마다 파일 전체를 새로 쓴다.** 2GB 영상이면 2GB 를 복사하고 그만큼 빈 공간이 필요하다 (모아서 쓰기를 고른 까닭 중 하나)
4. 명령줄로 한글을 넘기면 글자가 깨진다 → exiftool 에 인자를 UTF-8 파일(`-@`, 지금 `lib/exiftool.js` stay_open 방식)로 넘긴다. `-P` 로 파일 수정 시각을 그대로 둔다

## 쓰는 칸
| 형식 | 쓰는 칸 | 읽을 때 |
|---|---|---|
| JPG | XMP `dc:subject` + IPTC `Keywords`(UTF-8) + `XPKeywords`(탐색기가 고친 값과 어긋나지 않게 셋을 같게) | 세 칸을 합침 |
| PNG · WEBP · GIF · TIFF · DNG · HEIC | XMP `dc:subject` | `dc:subject` |
| MP4 · MOV · M4V · 3GP | XMP `dc:subject` + `Microsoft:Category` | 두 칸을 합침 |
| BMP · AVI · MKV · WMV | 쓰지 않음 (DB 에만, ⚠️ "이 PC 에만 있는 태그") | — |

## 설계
- **원본은 늘 DB 가 아니라 파일.** 폴더를 다시 읽을 때(`lib/library.js`) 위 칸의 태그를 읽어 `file_tags` 에 넣는다. 종류 태그만 따로(`mediaType`), 나머지는 모두 같은 태그. 다른 PC 에서 백업 폴더를 열면 첫 읽기에서 태그가 그대로 돌아온다
- **"파일에 안 쓴 태그" 상태**: `manual_tags` 의 붙이기 · 떼기는 "쓸 것 목록"이 된다. 갤러리 · 태그 화면 위에 "파일에 쓰지 않은 태그 N장 · 파일에 태그 쓰기" 띠를 둔다
- **쓰기 순서** (사진 한 장씩, 묶음 하나 = 되돌리기 줄 하나)
  1. 미리보기: 바뀌는 파일 수 · 형식별 수 · 큰 영상 합계 크기 · 못 쓰는 형식 수 · 필요한 빈 공간을 보여 줌. 버튼은 "N장 파일에 태그 쓰기"
  2. 쓰기 직전 파일 서명(크기 · 수정 시각)이 미리보기 때와 같은지 확인. 다르면 그 파일은 건너뛰고 "바뀐 파일"로 남김
  3. 쓰기 전 바이트 지문 · 내용 지문 · 이전 태그 목록을 기록 파일에 먼저 적음 (기존 `manual-edits.jsonl` 과 같은 "먼저 적고 나서 실행")
  4. exiftool 로 쓰기 (`-overwrite_original -P`, 목록 전체). exiftool 은 `이름_exiftool_tmp` 를 만든 뒤 바꾸므로 중간에 꺼져도 원래 파일은 그대로. 남은 임시 파일은 다음에 켤 때 지움 (`lib/runner.js` 와 같은 이름 규칙)
  5. 다시 읽어 태그 목록이 맞는지 · 내용 지문이 같은지 확인. 영상은 재생 확인. 다르면 실패로 적고 알림
- **되돌리기**: 기록의 이전 태그 목록을 같은 방법으로 다시 씀 (휴지통 · 영구 삭제 없음)
- **중간에 멈춤 · 실패**: 기록에 "쓴 파일 / 아직"이 남아 있어 다음에 "이어서 쓰기"로 남은 것만. 실패한 파일은 DB 에 그대로 "안 쓴 태그"로 남아 띠에 계속 보임
- **닫을 때 알림**: 안 쓴 태그가 있으면 창을 닫기 전에 묻기 ("지금 쓰기" / "다음에", 다음에를 골라도 DB 에는 남아 있음)
- **라이브 포토**: 사진과 짝 영상에 같은 태그를 같이 씀
- **가져오기 전 거르기 태그(#126) · 돌리기(#138)**: 같은 "쓸 것 목록"으로 들어감. 돌린 복사본 · 원본 바꾸기는 지금처럼 정보를 복사하므로 파일 태그가 따라감
- **쓰는 대상**: 지금 백업 폴더의 파일만. 가져올 폴더(원본)에는 쓰지 않음

## 기존 태그 옮기기 (DB 에만 있는 것)
- 첫 실행 때 자동으로 하지 않는다. 위 "파일에 안 쓴 태그 N장" 띠에 그대로 잡히므로 같은 미리보기 → 쓰기로 옮긴다
- 옮기기 전에 이 PC 의 `library.db` · `manual-edits.jsonl` 은 그대로 둔다 (실패해도 DB 에서 다시 쓸 수 있게)
- 다 옮긴 뒤 다른 PC 에서 백업 폴더를 열어 태그가 돌아오는지 확인 (사용자 확인 항목)
