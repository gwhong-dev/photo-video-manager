# 사진 · 영상 돌리기 · 자르기 · 나누기 방식 (2026-11-23)

## 왜
갤러리에서 누운 사진 · 영상을 돌려 저장하고, 영상은 아이폰 사진 앱처럼 앞뒤를 자르거나 여러 개로 나누고 싶다 (사용자 요청, `PROGRESS.md` 나중에 할 일 23).
지금 프로그램에는 파일 내용을 바꾸는 편집이 없었다. 원본을 바꾸는 기능이라 등급은 L.

## 정한 것 (사용자 선택)
| 질문 | 고른 것 | 버린 안 · 이유 |
|---|---|---|
| 자르는 자리 | **고른 자리에서 정확히** (영상을 새로 저장) | 다시 저장하지 않고 자르기(빠름, 화질 그대로): 영상은 몇 초마다 있는 "기준 화면"에서만 끊을 수 있어서, 3.2초를 골라도 앞의 기준 화면(예: 2초)부터 잘림. 사용자가 "아이폰처럼 고른 자리"를 원함 |
| 오래 걸리는 저장 | **뒤에서(백그라운드)** 돌고 갤러리는 계속 씀 | 창을 띄워 두고 기다리기: 몇 분 동안 다른 일을 못 함 |
| 나눈 조각의 촬영 시각 | **원본 시각 + 조각 시작 위치** | 모두 원본과 같은 시각: 날짜 칸에서 순서가 섞임 |
| 저장 방식 | **복사본 저장 / 원본 바꾸기 둘 다**. 원본 바꾸기는 옛 원본을 휴지통으로 (영구 삭제 없음) | 원본만 바꾸기: 되돌리기 어려움 |
| 실행 전 | 미리보기(돌린 모습 · 조각 목록)를 보고, 결과를 말하는 버튼으로 실행 | — |

화질 설명 (사용자 질문 "많이 떨어짐?"): 다시 저장할 때 높은 품질 설정을 쓰면 눈으로는 거의 차이가 없다. 대신 파일 크기가 조금 달라지고 시간이 걸린다.

## 돌리기 (이번 PR)
화질을 잃지 않게 **방향 정보만** 바꾼다. 원본은 그대로 두고 늘 새 파일을 만든 뒤 옮긴다 (`lib/media-edit.js`).

| 형식 | 방법 | 이유 |
|---|---|---|
| JPG | EXIF Orientation 값만 바꿈 (exiftool) | 픽셀을 다시 저장하면 JPG 는 화질이 조금씩 떨어짐 |
| MOV · MP4 · M4V | 영상 회전 정보(Rotation)만 바꿈 (exiftool) | 다시 압축하지 않음. ffmpeg `-display_rotation -c copy` 도 되지만 iPhone 메타(Keys) 를 다시 붙여야 해서 exiftool 이 더 단순 |
| PNG | 픽셀을 돌림 (sharp) + 원래 정보 다시 넣기 | 화면 캡처 등 PNG 는 방향 정보를 무시하는 프로그램이 많음. PNG 는 손실 없는 압축이라 화질 그대로 |
| HEIC | **아직 안 함** (버튼 숨김) | 방향을 EXIF 와 그림 정보(irot) 두 군데에 적어서 한쪽만 바꾸면 프로그램마다 다르게 보임 |

- 라이브 포토: 사진과 짝 영상을 같이 돌린다. 복사본은 사진 · 짝 영상이 같은 번호(`이름_1.jpg` · `이름_1.mov`)를 써서 짝이 유지된다
- 원본 바꾸기 순서: 돌린 임시 파일을 모두 만든 뒤 → 확인 창에서 본 것과 그대로인지 다시 확인 → 옛 원본을 휴지통으로(기존 `discardFiles`) → 임시 파일을 원래 자리에. 휴지통으로 못 옮긴 파일은 바꾸지 않는다. 마지막 이름 바꾸기가 실패하면 돌린 파일을 지우지 않고 남겨 두고 알린다 (옛 원본은 휴지통에서 되살릴 수 있음)
- 원본 바꾸기는 **확인 창(미리보기)을 본 뒤에만** 된다. 미리보기는 한 번 쓰면 잊으므로 실패한 뒤에는 화면이 미리보기를 새로 받아 온다 (#138 검증)
- 휴지통 결과를 못 받았어도(오류) 원본 자리가 비어 있으면 돌린 파일을 그 자리에 둔다 → 빈 자리가 남지 않음 (#138 검증)
- 파일을 둘 때는 **덮어쓰지 않는 방법**(하드 링크, 안 되면 "없을 때만 복사")을 쓴다. 그사이 같은 이름 파일이 생기면 그 파일을 지키고 돌린 파일은 임시 폴더에 남긴다. 저장 중에는 가져오기 화면도 막는다 (#138 검증)
- 돌린 파일의 **수정 시각은 돌린 시각**이 된다 (일부러): 다시 읽기 · 썸네일 주소(`?v=`)가 수정 시각으로 바뀐 걸 알아채기 때문. 촬영일(EXIF) · 날짜 폴더는 그대로
- 임시 파일은 같은 폴더의 `.pvm-edit` 안에 만든다: 같은 드라이브라 이름 바꾸기만으로 옮겨지고, 점(.)으로 시작하는 폴더는 갤러리가 읽지 않는다
- 복사본에는 직접 넣은 날짜 · 위치와 내가 붙인 태그(DB)도 따라간다 (`db.copyManual`). 새 이름에 옛 값이 남아 있었으면 지우고 원본 값으로 덮는다. 단 기록 파일(`manual-edits.jsonl`)에는 안 적는다: 값 넣기 묶음으로 적으면 "되돌리기"에 섞이기 때문 → 나중에 할 일 30
- 화면: 자세히 보기 패널의 "왼쪽으로 돌리기 / 오른쪽으로 돌리기" → 미리보기만 돈다 → "돌린 복사본 저장" / "돌린 모습으로 원본 바꾸기" / "돌리기 취소"
- 저장 뒤 썸네일 · 큰 그림은 파일 수정 시각을 주소에 붙여(`?v=`) 새로 그린다

## 자르기 · 나누기 (다음 PR)
- 영상 재생(별도 세션)이 머지된 뒤 그 재생기 위에 만든다
- 원본 코덱에 맞춰 다시 저장 (HEVC → libx265 10bit, H.264 → libx264, 높은 품질). HDR 색 정보는 유지, 돌비 비전 정보만 빠짐
- 위치 · 기기 · 태그 등은 원본과 같게, 촬영 시각만 조각 시작 위치만큼 더함
- 저장은 차례로 하나씩 뒤에서, ffmpeg 은 낮은 우선순위. 저장 중인 파일만 다른 편집 · 휴지통을 막음
