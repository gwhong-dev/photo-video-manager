# 해외 영상 시간대 맞추기 (2026-11-27)

## 문제
- 아이폰 영상은 "현지 시각 + 시간대"(`Keys:CreationDate`, 예: `2019:08:13 20:40:00-07:00`)를 적어서 이미 맞게 정리돼요.
- 안드로이드 · 디지털카메라 영상은 QuickTime `CreateDate` 에 세계 표준시(UTC)만 적어요. exiftool(`-api QuickTimeUTC`)이 이것을 **이 PC 시간대**로 바꿔 주기 때문에, 해외에서 찍은 영상은 한국 시간으로 바뀌어 날짜 폴더가 하루 밀릴 수 있어요.
  - 예: 미국 서부(-07:00) 8월 13일 저녁 8시 30분 → 한국 8월 14일 낮 12시 30분 → `2019/08/14` 폴더

## 고른 방식: 차례로 시도하는 조합 (사용자 결정)
1. 영상에 시간대가 든 촬영 시각이 있으면 그대로 (아이폰, 지금도 됨)
2. 영상 GPS → 시간대 지도 (B) — **다음 PR**. 새 부품(의존성)이라 L, 크기 · 정확도를 비교해 보여 주고 승인 뒤 추가
3. 같은 폴더에서 12시간 안에 찍은 사진의 시간대(`OffsetTimeOriginal`)를 빌림 (C) — **이번 PR**, 가장 가까운 사진 하나
4. 셋 다 없으면 지금처럼 이 PC 시간대 (D)

- GPS(2)를 사진(3)보다 앞에 두는 이유: GPS 는 영상을 찍은 그 자리라 가장 직접적인 증거예요. 몇 시간 전 사진은 비행기로 시간대를 넘기 전일 수 있어요.
- 맞춘 시간대는 계획의 `zone` 칸(예: `-07:00 (사진)`)과 작업 로그 `시간대:` 에 남겨요.

## 버린 안
- A 경도로 어림(15도 = 1시간): 중국(넓어도 +08:00) · 인도(+05:30) · 서머타임에서 틀려요. 같은 GPS 로 B 가 더 정확하게 답하니 B 가 들어오면 할 일이 없어요.
- B 만 쓰기: GPS 를 끈 카메라 영상은 못 고쳐요 → C 와 같이.
- C 만 쓰기: 같은 여행 사진이 없으면 못 고쳐요 → B 와 같이.

## 범위 · 한계

- 같은 폴더 사진만 봐요 (폰은 사진과 영상을 같은 폴더에 둠). 다른 폴더 사진까지 보면 다른 여행 사진을 빌릴 수 있어요.
- 갤러리는 아직 이 PC 시간대로 보여 줘요 (백업된 영상 파일의 UTC 시각은 그대로라서). PROGRESS.md 나중에 할 일.
