# 2026-11-24 이름만 다른 같은 영상: 화면 데이터 지문으로 중복 찾기 (PR #141)

## 문제
- 사용자 실사용: "영상을 분류할 때 완전 중복도 못 잡아 2개씩 분류됨"
- MOV 는 MP4 로 바꿔 저장해요(lib/processor.js, `-c:v copy`). 그래서 원본 MOV 와 백업 MP4 는 크기 · 바이트 지문이 달라 바이트 비교(②)에 안 걸려요
- 변환 영상의 내용 비교는 애플 ID(ContentIdentifier) 로만 했는데(④), 이 ID 는 라이브 포토 영상에만 있어요
- → 보통 아이폰 영상을 이름 · 폴더만 다르게(`IMG_0001(1).MOV`, 다른 폴더의 같은 영상) 다시 가져오면 새로 저장됐어요

## 고른 방식: ffmpeg 화면 데이터 지문
- `ffmpeg -i 파일 -map 0:v:0 -c copy -f hash -hash sha256 -` = 첫 영상 트랙의 압축 데이터만 지문으로 만들어요
- 변환이 화면 데이터를 그대로 옮기므로, 원본 MOV 와 결과 MP4 의 이 지문은 똑같아요 (점검 68a 가 실제 변환으로 확인)
- 다른 촬영이 같은 지문이 될 일은 사실상 없어요 (화면 데이터 전체의 SHA256)

## 비교 범위 (속도)
- 지문은 파일을 끝까지 읽어서 느려요. 그래서 후보를 먼저 줄여요
  - 같은 날짜 폴더의 `.mp4` 만 (결과가 들어갈 폴더)
  - 크기가 원본의 0.3배 ~ 1.05배(+1MB): 화면 데이터가 같으면 결과는 원본보다 조금 작거나 거의 같아요. 소리 트랙이 여러 개인 원본은 작아질 수 있어 아래쪽을 넉넉히 뒀어요
  - 가로 · 세로가 같은 것만 (가로 · 세로가 바뀐 것은 같다고 봄, 정보를 모르면 빼지 않음) — 검증 ⑤
- 한 파일의 지문은 한 번만 계산해요

## 원본 정리 (되돌리기 어려운 쪽이라 보수적으로)
- 미리보기에서 `sameVideo` 표시를 남기고, 정리 직전에 지문을 다시 비교해요
- 지문이 같아도 **원본의 촬영 날짜가 백업과 다르면 남겨요** (날짜만 고친 사본을 정리하면 고친 날짜가 백업에 없어서) — 검증 ①
  - 원본에 날짜가 없으면 잃을 것이 없어서 정리 대상
- 비교 함수 · 정보 읽기 · ffmpeg 중 하나라도 없으면 정리하지 않고 남겨요
- 바이트가 같은 쌍둥이 원본(①에서 묶임)도 표시를 이어 받아 같이 정리 후보 — 검증 ③

## 버린 안
- 파일 전체 바이트 지문: MOV 와 MP4 는 상자 구조가 달라 항상 달라요
- 촬영 날짜 + 길이 + 가로 · 세로로 같다고 보기: 연속으로 찍은 다른 영상을 같은 것으로 볼 위험 (원본 정리까지 이어지면 되돌리기 어려움)
- 실행 단계에서 비교: 미리보기에 "이미 있음"이 안 보여 사용자가 미리 알 수 없어요
