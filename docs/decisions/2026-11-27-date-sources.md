# 날짜 출처 보완: Google Takeout JSON · 13자리 밀리초 이름 (2026-11-27)

필수 기능 조사(`docs/필수기능-순위-조사.md`) Top 5 의 ①. 촬영 정보가 없는 사진이 "내려받은 날"이나 "_날짜없음"으로 가는 경로를 줄인다.

## 무엇을 바꿨나
- 날짜 찾는 순서: **촬영 정보 → 파일 이름 → 구글 정보(Takeout JSON) → 앨범 정보(iCloud AlbumInfo.json)** → 없으면 `_날짜없음`
- 구글 정보: Takeout 은 진짜 찍은 시각을 사진 옆 JSON 의 `photoTakenTime.timestamp`(세계 표준시 초)에 둔다. 이 PC 시간대로 바꿔 날짜 폴더를 정한다 (앨범 정보와 같은 방식)
  - JSON 이름 모양: `IMG_1.jpg.json`(예전) · `IMG_1.jpg.supplemental-metadata.json`(2024년 뒤) · 51자 제한으로 잘린 이름 · 같은 이름 두 번째 사진 `IMG_1(1).jpg` 의 `IMG_1.jpg(1).json` · 편집본 `IMG_1-edited.jpg` 는 원본 JSON
  - 이름으로 짝을 못 찾으면 JSON 안의 `title`(원래 파일 이름)로 찾되, 같은 title 이 둘 이상이면 쓰지 않는다 (틀린 날짜보다 날짜없음이 낫다)
  - `creationTime`(구글에 올린 시각)은 쓰지 않는다
- 파일 이름: 이미 읽던 `YYYYMMDD` 모양(카카오톡 · WhatsApp `IMG-YYYYMMDD-WA` · 스크린샷 · 텔레그램) 에 더해, 이름 맨 앞의 13자리 밀리초(`FB_IMG_` · `mmexport` · `wx_camera_` 머리말 또는 이름 전체)도 날짜로 읽는다

## 고른 이유
- 파일 이름을 구글 정보보다 먼저 둔 까닭: 촬영 정보가 지워진 메신저 사진은 Takeout 의 photoTakenTime 이 "구글에 올린 시각"으로 채워진 경우가 있다. 이름 속 날짜(받은 날)가 더 가깝고, 지금까지 이름 날짜로 정리되던 파일의 결과가 바뀌지 않는다
- 13자리 밀리초는 아무 이름에서나 찾지 않고 이름 맨 앞에서만: `IMG_1711627512345` 처럼 다른 숫자 이름을 날짜로 잘못 읽지 않게

## 버린 안
- 사진 파일에 JSON 날짜를 써 넣기(exiftool 로 DateTimeOriginal 쓰기): 원본 바이트가 달라져 중복 판단 · 원본 정리 비교가 복잡해진다. 지금처럼 이름 앞 날짜로 남기면 갤러리도 그 날짜를 읽는다
- 잘린 이름을 앞부분만 맞춰 보는 방식: 비슷한 이름이 많은 폴더에서 엉뚱한 JSON 과 짝지어질 수 있다

## 남은 것
- 해외에서 찍은 영상의 시간대(Keys:CreationDate 가 없는 안드로이드 · 카메라 영상은 한국 시간으로 바뀜)는 방식을 골라야 해서 따로 (`PROGRESS.md` 사용자 확인 · 질문)
- 이미 `_날짜없음` 에 들어간 Takeout 사진을 JSON 날짜로 옮기는 것("날짜없음 채우기"에 구글 정보 더하기)은 나중에 할 일
