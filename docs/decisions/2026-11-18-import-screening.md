# 가져오기 전 거르기 + 가져올 때 태그 한 번에 (2026-11-18 결정, #126)

> 설계: `docs/superpowers/specs/2026-11-18-import-screening-design.md` · 등급 L

## 왜
- 7만 장 첫 정리는 끝났고, 앞으로는 수백~수천 장을 한 번씩 가져와요 (예: `I:\무제`, 에버랜드 삼성라이온즈 경기 약 200장)
- 지금은 비슷한 사진 화면이 라이브러리(백업 폴더)만 봐서, 다 가져온 뒤에야 거를 수 있고 새 사진이 6만 장 사이에 섞여요
- 사용자가 원하는 순서: 가져올 폴더에서 먼저 거르기 → 평소처럼 가져오기(이름 · 변환 · 날짜 폴더) → 가져온 사진 전체에 태그 하나

## 고른 것
| 결정 | 내용 | 누가 |
|---|---|---|
| 1번 휴지통으로 거르기 | 갤러리 엔진을 가져올 폴더에 잠깐 붙여 지금의 비슷한 사진 화면을 그대로 씀. 버린 사진은 가져올 폴더 쪽 휴지통 (없는 드라이브면 `가져올 폴더\_정리완료원본`, 미리보기가 이미 건너뜀) | 사용자 |
| 태그 (앨범 · 하위 폴더 아님) | 앱의 앨범은 iCloud 정보라 읽기 전용, 하위 폴더는 날짜 폴더 분류와 부딪힘 | Claude |
| 거르기 폴더는 메모리에만 | 설정 파일의 백업 폴더를 바꾸지 않아요. 앱을 끄거나 가져오기 화면으로 가면 끝 | Claude |
| 거르기 중 막는 기능 | 날짜 · 위치 넣기, 태그, 날짜없음 채우기, 위치 제안, 되돌리기, 지도, 정리 기록. 가져올 폴더 경로에 붙인 값은 가져오면 경로가 바뀌어 사라져요 | Claude |
| 거르기 폴더 계산기를 따로 | 지문 · AI 계산기를 거르기 폴더 몫으로 새로 만들고 끝낼 때 그것만 멈춤. 라이브러리 계산(AI 는 몇 시간)이 돌던 중이면 그 회차는 멈추고 새 계산기로 바꿔, 끝낸 뒤 다시 읽을 때 이어서 해요 | Claude |
| 태그 붙이는 때 | 회차가 끝나고 갤러리가 백업 폴더를 끝까지 다시 읽은(done) 뒤. 그 사이 거르기가 시작되거나 백업 폴더가 바뀌면 붙이지 않고 안내만 (#126 검증 ⚠️) | Claude |
| 태그 대상 | 그 회차의 완료 결과 파일 + 중복의 남는 파일 (첫 회차면 미리보기 때부터 중복이던 것도). "확인 필요"(비슷한 다른 버전) · 실패 · 이미 정리됨 · 백업 밖은 빼요. 이미 붙은 사진은 그대로 | Claude |
| 되돌리기 | 지금 태그 붙이기와 같은 길(tagAdd 묶음 1개, 기록 파일 먼저) → 갤러리 "내가 넣은 정보"의 되돌리기 줄로 한 번에 뗌 | Claude |

## 버린 안
- 계획에서만 빼기(2번): 고르는 화면 · 원본 정리 규칙을 새로 만들어야 해서 몇 배 큼
- 가져온 뒤 "이번 사진만" 보기: 버릴 사진이 라이브러리에 잠깐 들어감 (사용자가 "먼저 거르고 옮기기"를 원함)
- 거르기에서 "하위 폴더 포함" 따르기: 갤러리 읽기는 늘 하위 폴더까지 읽어요. 지금은 꺼 둔 채 거르기를 누르면 한 번 알려 줘요 (되돌릴 수 있는 이동이라 위험은 낮음)
