# 원본 정리 확인 창의 중복 원본 비교 (2026-11-18, PR #125)

## 왜
2026-11-18 가져온 218개 중 "중복 10"(라이브러리에 이미 같은 파일)이 원본 정리(휴지통 228개)에 같이 들어갔는데, 그 중복이 정말 같은 사진인지 정리 전에 눈으로 볼 수 없었다.
사용자 요청: 정리 창에서 왼쪽에 남는 것, 오른쪽에 사라지는 것을 미리보기로 나란히 보여 주고, 일괄 정리하거나 "이건 중복이 아니야, 남길게"로 뺄 수 있게.

## 정한 것
| 무엇 | 고른 방식 | 버린 안 · 이유 |
|---|---|---|
| 비교 대상 | 정리 대상 중 `dup` 원본만 (같은 파일 · 이미 있음 · 변환형 중복). 방금 변환 · 이름 바꿔 옮긴 원본(`done`)은 비교 없이 같이 정리하고 개수만 한 줄 | 전부 비교: 수천 개 중 대부분이 방금 옮긴 것이라 볼 가치가 낮고 창이 길어짐 (메인 결정) |
| 기본 선택 | 전부 정리 체크, 줄마다 체크를 풀면 "남김". 모두 남기기로 · 모두 정리하기로 버튼 | 기본 남김: 중복은 지문 · 애플 ID 까지 확인한 것이라 대부분 정리가 맞음 |
| 남김 기록 | 작업 기록 `cleanSkip: "사용자가 남김"` (#116 의 규칙 남김과 같은 칸). 원본은 그대로, 배너 후보 · 다음 정리 창에서 빠짐, 목록 메모에 까닭 | 따로 목록 파일: 기록 곳이 둘이 되고 작업이 바뀌어도 남음 |
| 남김 되돌리기 | 가져오기 미리보기를 새로 하면 새 작업이라 다시 물음 (따로 버튼 없음) | "남김 풀기" 버튼: 화면 · 기록이 늘어남. 필요해지면 나중에 |
| 작은 그림 | 갤러리 썸네일과 같은 방법(`lib/thumbs.js` photoBuffer · videoBuffer: sharp, 못 열면 ImageMagick, 영상은 FFmpeg 1초 장면)을 **메모리에만**(data 주소), 임시 파일은 `userData\compare-tmp` | 갤러리 썸네일(`pvm://thumb/<id>`) 다시 쓰기: 가져올 폴더의 원본은 갤러리 DB 에 없고, `gallery-main.js` 를 고쳐야 함 · 디스크 캐시: 한 번 보고 마는 그림이라 필요 없음 |
| 많을 때 | 줄은 100개씩 "더 보기", 그림은 보이는 줄만(IntersectionObserver), 동시에 2개, 300개만 기억, 창을 닫으면 그만 만듦 | 전부 한 번에: 수천 개면 HEIC · 영상 변환으로 몇 분 걸리고 메모리가 큼 |
| 크게 보기 | 그림을 누르면 Windows 기본 프로그램으로 열기 (샘플 확인과 같은 방식) | 창 안 큰 그림: 원본 전체 해상도 디코딩이 필요해 무거움 |
| 정리 직전 확인 | 그대로 (서명 · 표본, 휴지통 넘침 고르기). 남김을 **정리 직전 확인보다 먼저** 적어서 `mayClean` 이 대상에서 뺌 | 정리 뒤 빼기: 순서가 바뀌면 남긴 원본이 옮겨질 수 있음 |

## 안전
- 화면은 경로를 모르고 줄 번호와 `keep` / `src` 만 보낸다. 이상한 번호로 남기기를 부탁하면 정리 전체를 멈춘다 ("비교 목록을 다시 열어 주세요")
- 확인 창을 거치지 않았거나 다른 작업이면 남기기 번호를 받지 않는다
- 로그(`logs\clean_*`)에는 남긴 원본을 `#` 줄로 적고 끝 줄에 "사용자가 남김 N". 정리 화면 숫자(휴지통 · 이동)에는 세지 않는다
- 사진 폴더(가져올 · 백업)에는 아무것도 쓰지 않는다 (점검 58f)
- CSP 에 `img-src 'self' data:` 를 더했다 (그림을 data 주소로 받으려고). 스크립트 · 연결 허용은 그대로
