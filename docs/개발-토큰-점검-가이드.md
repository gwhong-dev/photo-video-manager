# 개발 프로젝트 토큰 점검 가이드 (다른 프로젝트에서도 그대로 쓰기)

> 만든 날: 2026-11-23. photo-video-manager 에서 실제 대화 기록을 집계해 토큰을 줄인 방법(PR #136, 근거 `docs/decisions/2026-11-23-token-diet.md`)을 다른 저장소에서 그대로 따라 하도록 정리했어요.
> 쓰는 법: 다른 프로젝트의 Code 탭 세션에서 "photo-video-manager 의 `docs/개발-토큰-점검-가이드.md` 대로 이 저장소 토큰 점검하고 PR 해줘" 라고 말하면 돼요.

## 0. 핵심 한 줄
**짐작하지 말고 대화 기록을 집계한다.** 처음엔 "점검 출력 · 규칙 문서 · 검증 에이전트"가 범인이라고 짐작했지만, 실제로는 각각 1~11% 였고 **긴 대화를 말할 때마다 다시 읽는 값이 70% 이상**이었어요.

| 프로젝트 (2026-11-23) | 대화 다시 읽기 | 20만 토큰 넘은 턴의 몫 | 에이전트 몫 |
|---|---|---|---|
| photo-video-manager | 73% | 68% | 11% |
| SuwonCultureMap | 75% | 59% | 8% |

## 1. 점검 (읽기만, 1~2분)
1. 아래 9절 스크립트를 세션의 임시 폴더(scratchpad)에 `token-audit.mjs` 로 저장 (저장소에는 넣지 않음)
2. `node token-audit.mjs <저장소 이름>` 실행 (예: `node token-audit.mjs SuwonCultureMap`). 대화 기록 폴더(`~/.claude/projects`) 중 이름이 들어간 것만 읽어요
3. 결과 1~5번을 아래 2절 표로 판정

## 2. 판정 표 (결과 → 처방)
| 결과에서 볼 것 | 이 값이면 | 처방 (3절 번호) |
|---|---|---|
| 2) 200k 넘는 칸 합계 | 30% 넘음 | ① 대화 길이 상한 (거의 항상 1순위) |
| 3) 상위 세션의 메시지 수 · 최대 대화 | 300개 넘음 · 50만 넘음 | ① + ② 주제마다 새 세션 |
| 1) 세션 시작 바탕 | 6만 넘음 | ③ 안 쓰는 플러그인 · 연결 도구 끄기 |
| 4) 파일 읽기 · 많이 읽은 파일 | 같은 큰 파일 10번 넘게 | ④ 큰 파일은 필요한 범위만 |
| 1) 에이전트 몫 | 15% 넘음 | ⑤ 검증은 바뀐 줄만 + 싼 모델 |
| 4) 점검 · 테스트, 5) 훅 | 각 3% 미만 | 손대지 않음 (효과 작음) |

## 3. 처방 묶음
① **대화 길이 상한 20만 토큰**: 저장소 `.claude/settings.json` 에 자동 요약 창을 넣는다 (Claude Code 공식 설정 `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, 10만 이상 토큰 수)
```json
{ "env": { "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "200000" } }
```
② **주제마다 새 세션**: 메인 세션은 15만 토큰(`get_usage`)을 넘으면 하던 PR 이 끝난 시점에 새 세션으로 넘긴다. 로그 분석 · 새 기능 설계 · 다른 기능 구현은 각자 세션. 넘기기 전에 결정을 저장소 파일(PROGRESS.md · 결정 기록)에 적는다

③ **시작 바탕 줄이기**: 그 프로젝트에서 안 쓰는 플러그인은 `.claude/settings.json` 의 `enabledPlugins` 에서 `false` (프로젝트 설정이 사용자 설정보다 우선). 계정 연결 도구(Canva · Figma · Notion · Drive 등)는 사용자가 앱에서 끈다

④ **큰 파일은 필요한 범위만**: 500줄 넘는 파일은 `grep -n` 으로 줄을 찾고 그 범위만 읽는다. diff 는 `--stat` 먼저. 같은 범위 다시 읽기 금지 (예외: 자동 요약 뒤 · 파일이 바뀐 뒤)

⑤ **검증 · 분기 모델**: 중간 위험 변경의 검증 에이전트는 바뀐 줄만 + `sonnet`, 큰 위험(원본 · 삭제 · DB · 배포 · 규칙)은 전체 검증 + `opus`. 분기 세션은 `start_session` 의 `model` 에 직접 적는다 (비우면 메인 모델을 따라감)

## 4. 그 저장소 CLAUDE.md 에 넣을 문단 (그 프로젝트 말투에 맞게 다듬기)
```
## 토큰 규칙 (근거: docs/decisions/YYYY-MM-DD-token-diet.md)
- 대화 길이 상한 20만 토큰: .claude/settings.json 의 CLAUDE_CODE_AUTO_COMPACT_WINDOW 로 자동 요약. 결정 · 다음 할 일은 요약 전에 저장소 파일에 적는다
- 주제가 바뀌면 새 세션. 메인은 15만 토큰을 넘으면 하던 PR 끝에 새 세션으로 넘긴다
- 500줄 넘는 파일은 통째로 읽지 않는다: grep -n 으로 줄을 찾고 그 범위만. diff 는 --stat 먼저. 같은 범위 다시 읽기 금지 (자동 요약 뒤 · 파일 변경 뒤는 예외)
- 검증 에이전트: 중간 위험은 바뀐 줄만 + sonnet, 큰 위험은 전체 + opus. 분기 세션 모델은 start_session 의 model 에 직접 적는다
- 이 프로젝트에서 안 쓰는 플러그인은 꺼 둔다
```

## 5. PR 절차
1. 브랜치 `chore/token-diet` (그 저장소의 브랜치 규칙을 따름)
2. 바꾸는 것: `.claude/settings.json` (① · ③), `CLAUDE.md` (4절 문단), 결정 기록 `docs/decisions/YYYY-MM-DD-token-diet.md` (1절 결과 숫자 · 고른 처방 · 버린 안), 그 저장소의 작업 기록 한 줄
3. 규칙 · 설정 파일이라 그 저장소에서 가장 높은 위험 등급으로 다룬다: 독립 검증 1회(숫자는 스크립트를 다시 돌려 맞추게) → 지적은 같은 PR 에서 고침 → CI → **사용자 "머지" 승인 뒤** 머지
4. 공개 저장소면 결정 기록 · PR 에 사는 곳을 짐작할 수 있는 내용(자주 찍은 위치 등) · 절대 경로 · 계정 이름을 적지 않는다

## 6. 머지 뒤 확인
- 새 세션에서 `get_usage`: 자동 요약 기준이 20만 근처로 바뀌었는지, 세션 시작 바탕이 줄었는지
- 프로젝트 `.claude/settings.json` 의 `env` 는 사용자가 그 폴더를 신뢰한 뒤에 적용돼요. 안 바뀌면 같은 값을 사용자 설정(`%USERPROFILE%\.claude\settings.json`)에 넣을지 사용자에게 묻는다
- 1~2주 뒤 1절 스크립트를 다시 돌려 2) 의 200k 넘는 칸이 줄었는지 비교

## 7. 하지 말 것
- 집계 없이 "아마 이게 크겠지"로 처방하기 (2026-11-23 실제로 틀렸음)
- 안전 검증(큰 위험 변경의 전체 검증 · 사용자 머지 승인) 줄이기
- 스크립트나 결과의 세션 첫 메시지(개인 경로 · 질문이 보일 수 있음)를 저장소 · PR 에 그대로 붙이기. 숫자만 옮긴다

## 8. 새 프로젝트를 만들 때
계정 스킬 `new-dev-project` 가 셋팅 PR 을 만들 때 ① · ③ 설정과 4절 문단을 같이 넣도록 고친 판이 `docs/skills/new-dev-project-SKILL.md` 에 있어요. 사용자가 claude.ai 에서 그 스킬을 이 파일로 바꿔 올리면 돼요.

## 9. 점검 스크립트 (`token-audit.mjs`)
```js
// 토큰 점검: Claude Code 대화 기록(jsonl)에서 이 프로젝트가 토큰을 어디에 썼는지 집계 (읽기만 함)
// 실행: node token-audit.mjs <저장소 이름>   예) node token-audit.mjs photo-video-manager
// 가중치는 API 요금 비율 어림 (캐시 읽기 0.1 · 캐시 쓰기 1.25 · 출력 5 · 입력 1). 요금제 한도 계산과 똑같지는 않음
import fs from 'node:fs'; import path from 'node:path'; import os from 'node:os';
const name = process.argv[2];
if (!name) { console.log('저장소 이름을 적어 주세요: node token-audit.mjs <이름>'); process.exit(1); }
const root = path.join(os.homedir(), '.claude', 'projects'); const files = [];
(function walk(d) { for (const e of fs.readdirSync(d, { withFileTypes: true })) { const p = path.join(d, e.name); if (e.isDirectory()) walk(p); else if (e.name.endsWith('.jsonl')) files.push(p); } })(root);
const mine = files.filter((f) => path.relative(root, f).split(path.sep)[0].toLowerCase().includes(name.toLowerCase()));
if (!mine.length) { console.log('기록을 찾지 못했어요:', root, '아래 폴더 이름에', name, '이 들어간 것이 없음'); process.exit(1); }
const W = (u) => (u.input_tokens || 0) + 1.25 * (u.cache_creation_input_tokens || 0) + 0.1 * (u.cache_read_input_tokens || 0) + 5 * (u.output_tokens || 0);
const kind = (c) => /npm(\.cmd)? (run )?(check|test)|pytest|jest|vitest/.test(c) ? '점검 · 테스트' : /git diff/.test(c) ? 'git diff' : /\bgh /.test(c) ? 'gh' : /git (log|show)/.test(c) ? 'git log/show' : /\b(cat|sed -n|head|tail|grep|rg|Get-Content)\b/.test(c) ? '파일 읽기(셸)' : '기타';
const T = { w: 0, cr: 0, cc: 0, out: 0, inp: 0, sub: 0, turns: 0, bigCC: 0 }; const band = { '<100k': 0, '100-200k': 0, '200-400k': 0, '400k+': 0 };
const sessions = []; const out = {}; const reads = {}; const firsts = []; let hook = 0;
for (const f of mine) {
  const isSub = f.includes(`${path.sep}subagents${path.sep}`); const seen = new Set(); const ids = {}; const s = { w: 0, msgs: 0, max: 0, desc: '' }; let first = true;
  for (const ln of fs.readFileSync(f, 'utf8').split('\n')) {
    if (!ln) continue; let j; try { j = JSON.parse(ln); } catch { continue; }
    if (j.type === 'user' && typeof j.message?.content === 'string') { if (!s.desc) s.desc = j.message.content.replace(/<[^>]+>[\s\S]*?<\/[^>]+>/g, '').replace(/\s+/g, ' ').trim().slice(0, 50); if (j.message.content.startsWith('Stop hook feedback')) hook++; }
    if (j.type === 'assistant' && j.message?.usage) {
      for (const c of j.message.content || []) if (c.type === 'tool_use') ids[c.id] = c.name === 'Bash' || c.name === 'PowerShell' ? kind(String(c.input?.command || '')) : c.name === 'Read' ? 'Read|' + path.basename(String(c.input?.file_path || '')) : c.name.startsWith('mcp__') ? 'MCP 도구' : c.name;
      if (seen.has(j.message.id)) continue; seen.add(j.message.id);
      const u = j.message.usage, w = W(u), ctx = (u.input_tokens || 0) + (u.cache_creation_input_tokens || 0) + (u.cache_read_input_tokens || 0);
      T.w += w; T.cr += u.cache_read_input_tokens || 0; T.cc += u.cache_creation_input_tokens || 0; T.out += u.output_tokens || 0; T.inp += u.input_tokens || 0; T.turns++; if (isSub) T.sub += w;
      if ((u.cache_creation_input_tokens || 0) > 100000) T.bigCC += u.cache_creation_input_tokens;
      band[ctx < 1e5 ? '<100k' : ctx < 2e5 ? '100-200k' : ctx < 4e5 ? '200-400k' : '400k+'] += w;
      s.w += w; s.msgs++; s.max = Math.max(s.max, ctx); if (first && !isSub) { firsts.push(ctx); first = false; }
    }
    if (j.type === 'user' && Array.isArray(j.message?.content)) for (const c of j.message.content) if (c.type === 'tool_result' && ids[c.tool_use_id]) {
      const arr = Array.isArray(c.content) ? c.content : [{ type: 'text', text: String(c.content ?? '') }]; let len = 0; for (const x of arr) len += x.type === 'text' ? (x.text || '').length : x.type === 'image' ? 6000 : 0;
      const k = ids[c.tool_use_id]; if (k.startsWith('Read|')) { reads[k.slice(5)] ??= { n: 0, c: 0 }; reads[k.slice(5)].n++; reads[k.slice(5)].c += len; out.Read = (out.Read || 0) + len; } else out[k] = (out[k] || 0) + len;
    }
  }
  if (!isSub) sessions.push(s);
}
const pct = (v) => (100 * v / T.w).toFixed(1) + '%'; const M = (v) => (v / 1e6).toFixed(1) + 'M'; const K = (v) => Math.round(v / 1000) + 'k';
firsts.sort((a, b) => a - b); const base = firsts[Math.floor(firsts.length / 2)] || 0;
console.log(`[${name}] 기록 ${mine.length}개 · 턴 ${T.turns} · 가중 합계 ${M(T.w)}`);
console.log(`\n1) 비용이 어디서 나왔나`);
console.log(`   대화 다시 읽기(캐시 읽기) ${pct(0.1 * T.cr)} | 새로 올리기(캐시 쓰기) ${pct(1.25 * T.cc)} (그중 10만 넘게 통째로 다시 올림 ${pct(1.25 * T.bigCC)}) | Claude 출력 ${pct(5 * T.out)}`);
console.log(`   에이전트(서브 에이전트) 몫 ${pct(T.sub)}`);
console.log(`   세션 시작 바탕 중간값 ${K(base)} 토큰 → 턴마다 다시 읽는 값 약 ${pct(0.1 * base * T.turns)}`);
console.log(`\n2) 그 턴의 대화 길이별 비용 몫 (200k 넘는 쪽이 크면 "대화 길이 상한"이 1순위)`);
for (const [k, v] of Object.entries(band)) console.log(`   ${k.padEnd(9)} ${pct(v)}`);
console.log(`\n3) 비싼 메인 세션 상위 5개`);
for (const s of sessions.sort((a, b) => b.w - a.w).slice(0, 5)) console.log(`   ${pct(s.w).padStart(6)}  메시지 ${String(s.msgs).padStart(4)}  최대 대화 ${K(s.max).padStart(5)}  ${s.desc}`);
console.log(`\n4) 대화에 들어간 도구 결과 (글자 수)`);
for (const [k, v] of Object.entries(out).sort((a, b) => b[1] - a[1]).slice(0, 8)) console.log(`   ${K(v).padStart(6)}  ${k}`);
console.log(`   많이 읽은 파일: ` + Object.entries(reads).sort((a, b) => b[1].c - a[1].c).slice(0, 5).map(([k, v]) => `${k} ${v.n}번`).join(' · '));
console.log(`\n5) 그 밖: 훅이 다시 쓰게 한 횟수 ${hook}`);
```
