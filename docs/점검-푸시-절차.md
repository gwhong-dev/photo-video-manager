# 점검 · 커밋 · 푸시 절차

> Claude Code는 기능 작업을 마칠 때마다 이 문서 순서대로 **스스로** 진행하고, `PROGRESS-LOG.md`에 결과를 한 줄 추가한다.

### 점검 임시 폴더 (영구 삭제 예외)
"영구 삭제 금지" 규칙의 **유일한 예외**. 점검이 만든 샘플 **복사본** 폴더만 해당한다.
- 대상: `%TEMP%\pvm-check-<시각>` — 지우기 전에 코드로 확인: ① `%TEMP%` 바로 안 ② 이름이 `pvm-check-`로 시작 ③ 링크가 아닌 진짜 폴더
- 통과하면: 이번 폴더를 포함해 `pvm-check-` 폴더를 모두 지운다
- 실패하면: 원인을 볼 수 있게 **이번(가장 최근 실패) 폴더 1개만** 남기고 나머지는 지운다
- 그 밖의 파일·폴더(샘플 원본, 사진, 백업 폴더 등)는 이 예외에 해당하지 않는다

## 2. 커밋

- 점검을 통과했을 때만 커밋한다
- 지금 브랜치가 `main`이면 커밋하지 않고 멈춘다
- 커밋 전에 확인: 비밀 파일(`*recovery-codes*`, `.env`, 토큰)이 포함되지 않았는지
- 메시지는 한글로, 무엇이 바뀌었는지 한 줄로

## 3. 푸시

- `feature/...` 브랜치만 자동으로 푸시한다: `git push -u origin <브랜치>`
- **`main`에 직접 푸시하지 않는다.** main 합치기(merge)는 사용자가 확인한 뒤에만
- 푸시가 실패하면(로그인, 충돌 등) 억지로 해결하지 말고 멈추고 알린다
- 푸시하면 CI(`.github/workflows/check.yml`)가 GitHub의 Windows PC에서 `npm run check`를 실행한다. 수동 샘플 점검은 ⏭ 건너뛴다

## 4. PR과 main에 합치기

- PR을 올리고 CI 통과를 확인한다 (`gh pr create`)
- M·L 등급은 검증 에이전트 검토를 받는다 (CLAUDE.md 3절, 4절)
- 머지 전 확인
  - [ ] 이 PC(Windows)에서 `npm run check` 통과 (수동 샘플 포함)
  - [ ] CI 통과
  - [ ] 파일을 다루는 동작을 바꿨으면 실제 사진 **복사본**으로 한 번 실행해 봄 (`docs/실사용-테스트.md`)
  - [ ] `PROGRESS.md` 갱신, `PROGRESS-LOG.md`에 한 줄 추가
- 사용자가 "머지"라고 한 뒤에만 머지한다
