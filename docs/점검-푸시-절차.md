# 점검 · 커밋 · 푸시 절차

> Claude Code는 기능 작업을 마칠 때마다 이 문서 순서대로 **스스로** 진행하고, 맨 아래 "기록"에 결과를 한 줄 추가한다.
> 사용자가 따로 요청하지 않아도 된다.

## 1. 자동 점검 (`npm run check`)

`npm run check` 한 번으로 아래를 모두 검사한다. 하나라도 실패하면 커밋·푸시하지 않는다.

| # | 검사 | 통과 기준 |
|---|---|---|
| 1 | 앱 실행 | Electron 창이 오류 없이 뜨고 닫힌다 |
| 2 | 외부 도구 | exiftool, ImageMagick, FFmpeg를 찾는다 |
| 3 | 샘플 정리 | `test/samples`를 **임시 폴더에 복사한 뒤** 그 복사본으로 실행한다 (원본·실제 사진 사용 금지) |
| 4 | 폴더 구조 | 결과가 `YYYY\MM\DD`에 들어간다 |
| 5 | 파일 이름 | `YYYY-MM-DD_HHMMSS_원본이름` + B 규칙 |
| 6 | 영상 날짜 | MOV의 날짜가 `Keys:CreationDate`(찍은 날) 기준이다. 전송한 날이면 실패 |
| 7 | 변환 | HEIC → JPG, MOV → MP4 (재압축 없음) |
| 8 | 중복 | 같은 파일은 건너뛰고, 이름만 겹치면 `_1` |
| 9 | 날짜 없음 | 정보 없는 파일은 `_날짜없음`으로 간다 |
| 10 | 이어하기 | 중간에 멈춘 뒤 다시 실행하면 남은 것만 처리한다 |
| 11 | 로그 | plan / run 로그 파일이 생긴다 |
| 12 | 안전 | 휴지통 없는 드라이브에서 원본 정리를 시도하면 **삭제하지 않고 막는다** |

### 샘플 파일 (`test/samples`)
- HEIC 사진 1, 라이브 포토(HEIC + MOV) 1쌍, MOV 영상 1, JPG 1
- 카톡 이름 파일 1 (`KakaoTalk_20261028_210941.jpg`), 스크린샷 1
- 같은 파일 2개 (중복 검사용), 정보 없는 파일 1
- 실제 개인 사진은 넣지 않는다. 용량이 크면 git에 올리지 않고 `.gitignore`에 넣은 뒤 받는 방법을 README에 적는다

## 2. 커밋

- 점검을 통과했을 때만 커밋한다
- 지금 브랜치가 `main`이면 커밋하지 않고 멈춘다
- 커밋 전에 확인: 비밀 파일(`*recovery-codes*`, `.env`, 토큰)이 포함되지 않았는지
- 메시지는 한글로, 무엇이 바뀌었는지 한 줄로

## 3. 푸시

- `feature/...` 브랜치만 자동으로 푸시한다: `git push -u origin <브랜치>`
- **`main`에 직접 푸시하지 않는다.** main 합치기(merge)는 사용자가 확인한 뒤에만
- 푸시가 실패하면(로그인, 충돌 등) 억지로 해결하지 말고 멈추고 알린다

## 4. main에 합치기 전 (사용자 확인 필요)

- [ ] `npm run check` 통과
- [ ] 실제 사진 **복사본**으로 사용자가 직접 한 번 실행해 봄
- [ ] docs/개발개요-v3.md "바로 다음 할 일" 갱신됨
- [ ] 아래 기록이 채워짐
