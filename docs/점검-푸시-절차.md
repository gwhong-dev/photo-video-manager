# 점검 · 커밋 · 푸시 절차

> Claude Code는 기능 작업을 마칠 때마다 이 문서 순서대로 **스스로** 진행하고, `PROGRESS-LOG.md`에 결과를 한 줄 추가한다.
> 사용자가 따로 요청하지 않아도 된다.

---

## 1. 자동 점검 (`npm run check`)

`npm run check` 한 번으로 아래를 모두 검사한다. 하나라도 실패하면 커밋·푸시하지 않는다.

| # | 검사 | 통과 기준 |
|---|---|---|
| 1 | 앱 실행 | Electron 창이 오류 없이 뜨고 닫힌다 |
| 2 | 외부 도구 | exiftool, ImageMagick, FFmpeg를 찾는다 |
| 3 | 샘플 정리 | `test/samples`를 **임시 폴더에 복사한 뒤** 그 복사본으로 실행한다 (원본·실제 사진 사용 금지) |
| 4 | 폴더 구조 | 결과가 `YYYY\MM\DD`에 들어간다 |
| 5 | 파일 이름 | `YYYY-MM-DD_HHMMSS_원본이름` + B 규칙 |
| 6 | 영상 날짜 | MOV의 날짜가 `Keys:CreationDate`(찍은 날) 기준이다. 전송한 날이면 실패 |
| 7 | 변환 | HEIC → JPG, MOV → MP4 (재압축 없음) |
| 8 | 중복 | 같은 파일은 건너뛰고, 이름만 겹치면 `_1` |
| 9 | 날짜 없음 | 정보 없는 파일은 `_날짜없음`으로 간다 |
| 10 | 이어하기 | 중간에 멈춘 뒤 다시 실행하면 남은 것만 처리한다 |
| 11 | 로그 | plan / run 로그 파일이 생긴다 |
| 12 | 안전 | 휴지통 없는 드라이브에서 원본 정리를 시도하면 **삭제하지 않고 막는다** (하위 a~s: 이동·휴지통·정리 대상·공간·연결 폴더·폴더 고르기 규칙·휴지통 실패·드라이브 판단·결과 파일 확인·`_1` 이름·이어하기 예정 기록·같은 파일인지 모름·진행 표시·배너 개수·휴지통 설정 경고·바로 제거 설정·휴지통 설정 읽기) |

| 13 | 재생 불가 영상 | 샘플 복사본의 `moov`를 지우고 끝을 0으로 채운 가짜 손상 파일이 복사되지 않고 `⚠ 재생 불가`로 표시되며 원본 정리 대상에서 빠진다 (a~h: 복사 안 함·원본 그대로·정상 영상·표시와 로그·정리 대상·백업에 이미 있는 손상 파일·ffprobe 없음·검사 함수) |
| 14 | 갤러리 DB | 임시 폴더의 DB 파일로 확인한다 (실제 `userData` 사용 금지). 같은 파일을 두 번 저장해도 한 줄, 바뀐 파일은 썸네일 대기·태그 교체, 탭(전체·사진·영상·스크린샷) 개수, 날짜 없음은 맨 끝, `missing` 파일은 조회에서 빠지고 되돌리면 다시 나옴, 다른 폴더(root) 파일 제외, 태그 요약·필터, 썸네일 대기열, 깨진 DB 파일은 이름을 바꿔 보관하고 새로 만듦 |
| 15 | 갤러리 검색 | 임시 폴더의 DB로 확인한다. 검색어 해석(날짜 모양 해석표, `% _ \` 이스케이프, 빈 검색어), 파일 이름·태그·종류 태그 찾기와 AND, 날짜 낱말(`2026`, `2026-10`, `10.28` 등), 따옴표가 든 글자도 그냥 글자로 취급, 사라진 파일 제외, 가짜 6만 건에서 조회·검색이 1000ms 이하 |
| 16 | 갤러리 폴더 읽기 | 샘플을 처리한 백업 폴더의 **복사본**(임시 폴더)을 읽는다. 사진 폴더는 읽기만 한다. 읽기 전후 파일 내용·수정 시각 그대로, 영상 날짜는 촬영 정보, 날짜 없음, 다시 읽을 때 exiftool 호출 0번, 바뀐 파일만 다시 읽음, 없어지면 `missing`·돌아오면 복원, 폴더 없음·빈 폴더·찾은 뒤 폴더 사라짐·못 읽은 폴더(이름만 비슷한 폴더는 보호 안 함)에서는 `missing`을 만들지 않음, 후가공 폴더(`2025년도`) 제외, 특수문자 이름, 잘못된 날짜(0000:00:00)는 파일 이름 날짜로, 읽는 중 사라진 파일·읽는 중 오류(첫 묶음 유지, `missing` 0개, 다시 읽으면 전부 저장), 겹치지 않음(같은 Promise), 가져오기 우선(바쁜 동안 다음 묶음을 읽지 않음), exiftool 없음, 읽기 실패 파일은 다시 읽기에서만 재시도, `gallery-scan_` 로그, `test/samples` 원본 그대로 |
| 17 | 갤러리 썸네일 | 임시 폴더의 사진 복사본과 DB로 확인한다 (실제 `userData` 사용 금지). 사진·한글 폴더 경로·PNG·특수문자 이름(`사진 #1 100%.jpg`)이 webp로 만들어지고 긴 변 320 이하, 회전 정보(Orientation=6) 반영, 영상(mp4) 썸네일과 1초보다 짧은 영상, 손상 영상·0바이트·사진이 아닌 파일·폴더에서 사라진 파일은 `failed`이고 다음 파일은 정상, 실패 다시 시도(`retryFailed`)로 `none`, FFmpeg 없음(사진은 만들고 영상은 `failed`), 외부 프로그램 시간 초과(`runCmd`가 5초 안에 `timedOut`), 낡은 임시 파일은 썸네일로 안 침, 이미 있는 썸네일은 다시 안 만듦, 패널 미리보기(긴 변 1200px, 저장 안 함, 영상은 썸네일), 보이는 요청 동시 4개·최근 요청 먼저, 가져오기 중에는 백그라운드를 시작하지 않고 동시 2개, `stop` 뒤 임시 파일 없음, `gallery-thumbs_` 로그, `pvm://` 판단(`thumb/<id>` 200, 없는 id·글자·`..%2F`·다른 호스트·`1%20` 404, 잘못된 주소는 DB와 파일을 건드리지 않음), 사진 폴더에 파일이 생기지 않음 |

### 샘플 파일 (`test/samples`)
- HEIC 사진 1, 라이브 포토(HEIC + MOV) 1쌍, MOV 영상 1, JPG 1
- 카톡 이름 파일 1 (`KakaoTalk_20261028_210941.jpg`), 스크린샷 1
- 같은 파일 2개 (중복 검사용), 정보 없는 파일 1
- 실제 개인 사진은 넣지 않는다. 용량이 크면 git에 올리지 않고 `.gitignore`에 넣은 뒤 받는 방법을 README에 적는다
- 자동 샘플: `test/samples/auto/` (`npm run samples`로 만듦, git에 올림)
- 수동 샘플: `test/samples/manual/` (PhotoSync로 받은 HEIC·라이브 포토 등, **git 제외**). 없으면 해당 검사는 `⏭ 건너뜀 (수동 샘플 없음)`

### 점검 임시 폴더 (영구 삭제 예외)
"영구 삭제 금지" 규칙의 **유일한 예외**. 점검이 만든 샘플 **복사본** 폴더만 해당한다.
- 대상: `%TEMP%\pvm-check-<시각>` — 지우기 전에 코드로 확인: ① `%TEMP%` 바로 안 ② 이름이 `pvm-check-`로 시작 ③ 링크가 아닌 진짜 폴더
- 통과하면: 이번 폴더를 포함해 `pvm-check-` 폴더를 모두 지운다
- 실패하면: 원인을 볼 수 있게 **이번(가장 최근 실패) 폴더 1개만** 남기고 나머지는 지운다
- 그 밖의 파일·폴더(샘플 원본, 사진, 백업 폴더 등)는 이 예외에 해당하지 않는다

## 2. 커밋

- 점검을 통과했을 때만 커밋한다
- 지금 브랜치가 `main`이면 커밋하지 않고 멈춘다
- 커밋 전에 확인: 비밀 파일(`*recovery-codes*`, `.env`, 토큰)이 포함되지 않았는지
- 메시지는 한글로, 무엇이 바뀌었는지 한 줄로

## 3. 푸시

- `feature/...` 브랜치만 자동으로 푸시한다: `git push -u origin <브랜치>`
- **`main`에 직접 푸시하지 않는다.** main 합치기(merge)는 사용자가 확인한 뒤에만
- 푸시가 실패하면(로그인, 충돌 등) 억지로 해결하지 말고 멈추고 알린다
- 푸시하면 CI(`.github/workflows/check.yml`)가 GitHub의 Windows PC에서 `npm run check`를 실행한다. 수동 샘플 점검은 ⏭ 건너뛴다

## 4. PR과 main에 합치기

- PR을 올리고 CI 통과를 확인한다 (`gh pr create`)
- M·L 등급은 검증 에이전트 검토를 받는다 (CLAUDE.md 3절, 4절)
- 머지 전 확인
  - [ ] 이 PC(Windows)에서 `npm run check` 통과 (수동 샘플 포함)
  - [ ] CI 통과
  - [ ] 파일을 다루는 동작을 바꿨으면 실제 사진 **복사본**으로 한 번 실행해 봄 (`docs/실사용-테스트.md`)
  - [ ] `PROGRESS.md` 갱신, `PROGRESS-LOG.md`에 한 줄 추가
- 사용자가 "머지"라고 한 뒤에만 머지한다
