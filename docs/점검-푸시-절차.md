### 샘플 파일 (`test/samples`)
- HEIC 사진 1, 라이브 포토(HEIC + MOV) 1쌍, MOV 영상 1, JPG 1
- 카톡 이름 파일 1 (`KakaoTalk_20261028_210941.jpg`), 스크린샷 1
- 같은 파일 2개 (중복 검사용), 정보 없는 파일 1
- 실제 개인 사진은 넣지 않는다. 용량이 크면 git에 올리지 않고 `.gitignore`에 넣은 뒤 받는 방법을 README에 적는다
- 자동 샘플: `test/samples/auto/` (`npm run samples`로 만듦, git에 올림)
- 수동 샘플: `test/samples/manual/` (PhotoSync로 받은 HEIC·라이브 포토 등, **git 제외**). 없으면 해당 검사는 `⏭ 건너뜀 (수동 샘플 없음)`

### 점검 임시 폴더 (영구 삭제 예외)
"영구 삭제 금지" 규칙의 **유일한 예외**. 점검이 만든 샘플 **복사본** 폴더만 해당한다.
- 대상: `%TEMP%\pvm-check-<시각>` — 지우기 전에 코드로 확인: ① `%TEMP%` 바로 안 ② 이름이 `pvm-check-`로 시작 ③ 링크가 아닌 진짜 폴더
- 통과하면: 이번 폴더를 포함해 `pvm-check-` 폴더를 모두 지운다
- 실패하면: 원인을 볼 수 있게 **이번(가장 최근 실패) 폴더 1개만** 남기고 나머지는 지운다
- 그 밖의 파일·폴더(샘플 원본, 사진, 백업 폴더 등)는 이 예외에 해당하지 않는다

## 2. 커밋

- 점검을 통과했을 때만 커밋한다
- 지금 브랜치가 `main`이면 커밋하지 않고 멈춘다
- 커밋 전에 확인: 비밀 파일(`*recovery-codes*`, `.env`, 토큰)이 포함되지 않았는지
- 메시지는 한글로, 무엇이 바뀌었는지 한 줄로

## 3. 푸시

- `feature/...` 브랜치만 자동으로 푸시한다: `git push -u origin <브랜치>`
- **`main`에 직접 푸시하지 않는다.** main 합치기(merge)는 사용자가 확인한 뒤에만
- 푸시가 실패하면(로그인, 충돌 등) 억지로 해결하지 말고 멈추고 알린다

## 4. main에 합치기 전 (사용자 확인 필요)

- [ ] `npm run check` 통과
- [ ] 실제 사진 **복사본**으로 사용자가 직접 한 번 실행해 봄
- [ ] docs/개발개요-v3.md "바로 다음 할 일" 갱신됨
- [ ] 아래 기록이 채워짐
