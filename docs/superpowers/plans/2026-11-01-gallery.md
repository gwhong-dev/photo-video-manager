# 갤러리 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 백업 폴더의 사진과 영상을 DB에 저장하고, 썸네일과 날짜별 격자, 검색, 정보 패널이 있는 읽기 전용 갤러리를 만든다.

**Architecture:** 파일 읽기, DB, 썸네일, 검색은 Electron을 모르는 `lib/` 모듈로 만들어 일반 Node에서 점검한다. `gallery-main.js`가 이것을 IPC와 `pvm://` 프로토콜로 연결하고, React 화면은 id로만 데이터를 요청한다. 기존 가져오기 화면은 그대로 두고 창의 페이지를 바꿔 오간다.

**Tech Stack:** Electron 최신(45), `node:sqlite`, React 19, Vite, `@tanstack/react-virtual`, `sharp`, exiftool, FFmpeg, ImageMagick

**Spec:** `docs/superpowers/specs/2026-11-01-gallery-design.md`

## Global Constraints

- 코드 주석은 한글로 쉽게 쓰고, 파일 맨 위에 "파일 위치 / 역할" 주석을 둔다 (기존 파일과 같은 모양)
- 갤러리 코드에는 사진 파일의 삭제, 이동, 이름 바꾸기, exiftool 쓰기를 넣지 않는다. 쓰기는 `userData` 안의 DB, 썸네일, 로그뿐이다
- 영상 날짜는 `Keys:CreationDate`를 먼저 읽는다
- `lib/`의 새 파일은 `require('electron')`을 하지 않는다
- SQL은 `lib/db.js`에만, 값은 항상 매개변수로 넘긴다
- 점검은 임시 폴더의 샘플 복사본으로만 하고, 실제 사진과 실제 `userData`를 쓰지 않는다
- 색: 배경 #3B3A37, 사이드바 #33322F, 패널 #403F3B, 선 #55534E, 글자 #F1EEE6, 보조 글자 #B3AFA5, 흐린 글자 #8C887E, "정보 없음"만 경고 노랑 #E3B341. 색연필 빨강은 쓰지 않는다
- 글꼴 IBM Plex Sans KR. 가운뎃점으로 정보 잇기, 버튼 글자 끝의 →, 영어 대문자 라벨, 모든 칸을 같은 둥근 카드로 만들기 금지
- 커밋 메시지는 한글(feat/fix/refactor/chore/docs), main에 직접 커밋하지 않음. `npm run check`가 실패하면 커밋하지 않음
- 머지는 사용자가 "머지"라고 한 뒤에만

## Review Focus

각 줄의 테스트는 맡은 작업에 들어 있다.

1. 손상되었거나 아주 큰 영상(`IMG_2522.mp4` 같은 12GB 손상 파일): FFmpeg가 멈춰도 60초 뒤 실패로 넘어가고 나머지 썸네일은 계속 만든다 (작업 5)
2. 이름에 한글, 공백, `#`, `%`가 있는 파일: 읽기와 썸네일이 정상 동작한다 (작업 4, 5)
3. 읽는 도중 파일이 사라지거나 USB를 뺌: 앱이 죽지 않고 이미 저장한 묶음은 유지되며, 그 회차에 `missing` 표시를 하지 않는다 (작업 4)
4. 잘못된 촬영 정보(`0000:00:00`, 미래 날짜): 파일 이름 날짜를 쓰거나 날짜 없음으로 간다 (작업 4)
5. "다시 읽기"를 읽는 도중 또 누름: 읽기가 겹치지 않고 진행 중인 것을 돌려준다 (작업 4)

| 파일 | 역할 |
|---|---|
| `lib/db.js` (새) | DB 열기, 구조, 모든 SQL |

| `gallery-main.js` (새) | IPC, 프로토콜 등록, 읽기 시작 시점 연결 |
| `src/` (새) | React 화면 |

### 작업 3: 검색

**Files:** Create `lib/search.js`, Modify `lib/db.js`, `scripts/check-gallery.js`

**Interfaces:**
- Produces: `parseQuery(text) → [{ like, dateLike }]`. 낱말마다 `like`(이름, 태그용 이스케이프된 `%낱말%`)와 `dateLike`(`taken_day`용 LIKE 패턴 또는 null).
- 날짜 해석표: `2026`→`2026-%`, `2026-10` `2026.10` `2026년 10월`→`2026-10-%`, `2026.10.28` `2026-10-28`→`2026-10-28`, `10.28`→`%-10-28`. `2026년 10월`처럼 공백이 든 모양은 낱말로 나누기 전에 합친다. 한 자리 월과 일(`2026.1.5`)도 받는다.
- `db.listDays`, `db.listFiles`가 `filter.query`를 쓴다. 낱말끼리 AND, 낱말 안에서 이름 OR 태그 OR 날짜.

- [ ] **Step 1:** 항목 15 "갤러리 검색"을 쓴다.
  - `parseQuery('2026년 10월')`의 `dateLike === '2026-10-%'`, `parseQuery('10.28')`의 `dateLike === '%-10-28'`, `parseQuery('수원')`의 `dateLike === null`
  - `파일 이름 찾기`, `두 글자 태그 찾기` (`친구`), `낱말 두 개 AND`
  - `% 글자 그대로`: `100%` 검색은 `100%.jpg`만 찾고 `1000.jpg`는 안 찾음
  - `날짜 낱말이 태그도 찾음`: `2026`이 태그 `2026년도_44주차`인 2019년 사진도 찾음

### 작업 5: 썸네일과 `pvm://`

**Files:**

- Modify: `lib/tools.js`, `package.json`, `scripts/check-gallery.js`

**Interfaces:**

- Produces:
  - `createThumbs({ db, thumbDir, getTools, isBusy, logger, maker }) → { request(id) → Promise<경로|null>, preview(id) → Promise<{ buffer, type }|null>, startBackground(root), stop(), retryFailed(root) }`
