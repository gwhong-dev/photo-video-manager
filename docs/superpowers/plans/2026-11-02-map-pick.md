# 지도에서 위치 고르기 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 고른 사진들에 지도 클릭이나 장소 검색으로 정한 위치 하나를 미리보기를 거쳐 넣는다.

**Architecture:** 인터넷에 나가는 코드는 `lib/map-net.js` 하나이고 Electron을 모른다. 화면은 `pvm://tile/...`과 IPC만 쓰고 CSP는 그대로다. 값 넣기는 새 요청 모양 `{ source: 'pin', lat, lng }`만 더해 지금의 미리보기, 저장, 기록 파일, 되돌리기를 그대로 쓴다.

**Tech Stack:** Electron 45 (`net.fetch`), React 19, Vite, Leaflet 1.9.4

**Spec:** `docs/superpowers/specs/2026-11-02-map-pick-design.md`

## Global Constraints

- 사진 파일에 쓰지 않는다. DB 구조를 바꾸지 않는다 (v2 유지)
- `lib/`에서 Electron을 부르지 않는다. Electron 값은 `main.js`에서 받는다
- 지도 시작 전 연결 없음. 실패해도 자동 재시도 없음. 자동완성 없음. 지도 미리 받기 없음
- 검색어를 로그에 남기지 않는다. 설정 주소 값도 로그에 남기지 않는다 (키 이름만)
- User-Agent: `photo-video-manager/<package.json 버전> (https://github.com/gwhong-dev/photo-video-manager)`
- 점검은 진짜 인터넷에 나가지 않는다
- 주석은 쉬운 한글. 화면 글에 가운뎃점과 버튼 끝 `→`를 쓰지 않는다. 빨강 `#E0412F`, 노랑 `#E3B341`을 지도에 쓰지 않는다
- 커밋 메시지는 한글. 이 작업 폴더의 git 명령은 `git -c safe.directory=<작업 폴더> ...`로 쓴다 (전역 설정을 바꾸지 않는다)
- 점검 항목 모양: `{ no, name, run(env) } → [sub(label, pass, detail)]`. `row`, `sub`는 `scripts/check-gallery.js`에서 가져온다

## Review Focus

- 검색 응답이 늦게 도착: 그 사이 새 검색을 했거나 창을 닫았으면 옛 결과를 버린다 (Task 4, 35d)
- 지도 창이 열리는 순간 크기가 아직 정해지지 않음: 회색 지도로 남지 않는다 (Task 4, 35a)
- 인터넷 끊김과 결과 0건은 다른 일이다: 서로 다른 문장을 보여 준다 (Task 2, 33j와 Task 4, 35c)
- 넣는 중에 핀을 옮김: 눌렀을 때의 위치로 저장되고 지도는 잠긴다 (Task 4, 35e)
- 고른 사진에 파일 위치가 있는 사진이 섞임: `원래 값이 있음`으로 세고 기록 파일의 전 값으로 되돌린다 (Task 3, 34c)
