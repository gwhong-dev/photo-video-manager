## 1. 목표와 성공 기준

위치나 날짜가 없는 사진을 모아 보고, 사용자가 고른 값을 여러 장에 한 번에 넣는다. 값은 DB에만 저장하고, 사진 파일은 건드리지 않는다.

실제 백업 폴더 숫자 (2026-11-01, 33,838개 기준)

| 항목 | 개수 |
|---|---|
| 날짜 없음 | 0 |
| 위치 없음 | 4,700 |
| 위치 없음 중 스크린샷 | 1,423 |
| 위치 없음 중 스크린샷 제외 | 3,277 |

지금 실제로 필요한 일은 위치 넣기다. 날짜 기능은 앞으로 카톡 사진 등을 가져올 때를 위해 만든다.

성공 기준
- 위치 있는 사진 한 장에서 복사해 3,277장 중 원하는 사진에 붙여 넣을 수 있다
- 넣기 전에 항상 "전 → 후" 미리보기를 본다
- 파일이 바뀌어 다시 읽어도, DB가 깨져 새로 만들어도 직접 넣은 값이 남는다
- 마지막 작업부터 차례로 되돌릴 수 있고, 되돌리면 파일에서 읽은 값으로 돌아간다
- 이 기능을 쓰는 동안 사진 폴더의 파일은 하나도 바뀌지 않는다

## 4. DB (구조 버전 1 → 2)

지금까지 DB의 모든 값은 파일에서 다시 만들 수 있었다. 직접 넣은 값은 그렇지 않으므로 두 가지를 더한다.

**`files` 표는 칸을 바꾸지 않는다.** `taken_at`, `lat` 같은 칸은 계속 "화면에 보일 값"을 담는다. 그래서 기존 조회, 정렬, 검색 코드는 그대로 동작한다. `taken_at_source`, `location_source`에 `manual` 값이 새로 생긴다.

**새 표**

```sql
-- 직접 넣은 값. 파일을 다시 읽을 때마다 여기 값을 files에 다시 덮어 쓴다
CREATE TABLE manual_values (
  path TEXT PRIMARY KEY,      -- files와 표를 잇지 않고 경로로 잇는다 (읽기 전에 복구해도 값이 남도록)
  root TEXT NOT NULL,
  taken_at TEXT,              -- NULL이면 날짜는 직접 넣지 않음
  taken_offset TEXT,
  lat REAL, lng REAL,         -- NULL이면 위치는 직접 넣지 않음
  orig_known INTEGER NOT NULL DEFAULT 0,  -- 아래 orig_ 값을 파일에서 읽어 두었는지
  orig_taken_at TEXT, orig_taken_offset TEXT, orig_taken_day TEXT, orig_taken_at_source TEXT,
  orig_lat REAL, orig_lng REAL, orig_location_source TEXT
);

-- 작업 한 번 = 묶음 하나
CREATE TABLE edit_batches (
  id TEXT PRIMARY KEY,        -- 무작위 글자
  root TEXT NOT NULL,
  kind TEXT NOT NULL,         -- date | location | both
  count INTEGER NOT NULL,
  created_at TEXT NOT NULL,
  undone_at TEXT
);

-- 묶음이 바꾼 파일별 "이전 상태". 되돌릴 때 쓴다
CREATE TABLE edit_items (
  batch_id TEXT NOT NULL,
  path TEXT NOT NULL,
  before_json TEXT NOT NULL,  -- 바꾸기 전 manual_values 값 (없었으면 null)
  after_json TEXT NOT NULL,
  PRIMARY KEY (batch_id, path)
);
```

옮기기: 버전 1 DB를 열면 표만 추가하고 버전을 2로 올린다. 다시 읽기는 필요 없다.

**값 적용 규칙**
- 넣을 때: `manual_values`에 쓰고, 처음 넣는 파일이면 지금 `files` 값을 `orig_`에 보관한 뒤 `files`를 고친다. 한 트랜잭션으로 묶는다. 복구할 때 `files`에 아직 그 파일이 없으면 `orig_known`을 0으로 두고, 다음 읽기에서 채운다.
- 다시 읽을 때 (`upsertFiles`): 파일 값으로 저장한 직후, 같은 트랜잭션에서 `manual_values`가 있으면 `orig_`를 새 파일 값으로 고치고 직접 넣은 값을 다시 덮어 쓴다. 직접 넣은 값은 파일에 새 값이 생겨도 이긴다.
- 파일이 사라져도 (`missing`) `manual_values`는 지우지 않는다.
- 썸네일 상태는 건드리지 않는다.

**알려진 한계:** 경로로 잇기 때문에 앱 밖에서 파일을 옮기거나 이름을 바꾸면 연결이 끊긴다. 이 값은 표에 남고 새 경로에는 적용되지 않는다.

## 5. 기록 파일 (DB가 깨져도 값을 지키기)

`userData/manual-edits.jsonl`. 한 줄에 작업 하나를 JSON으로 적는다. 지우지 않고 뒤에 더하기만 한다.

```
{"type":"apply","batchId":"...","at":"...","root":"...","kind":"location","items":[{"path":"...","before":null,"after":{...}}]}
{"type":"undo","batchId":"...","at":"..."}
{"type":"void","of":"apply","batchId":"..."}
```

`void`는 바로 앞의 같은 묶음 줄(`of`가 `apply`면 넣기, `undo`면 되돌리기)이 DB에 저장되지 못했다는 표시다. 되돌리기도 넣기와 같은 순서로 저장한다.

순서
1. 기록 파일에 먼저 쓴다. 실패하면 작업을 거절하고 DB도 바꾸지 않는다.
2. DB 트랜잭션을 실행한다. 실패하면 `void` 줄을 더하고 오류를 알린다.

복구: 프로그램을 켤 때 기록 파일을 끝까지 읽어, DB에 없는 묶음과 되돌림을 순서대로 적용한다. `void`가 붙은 묶음은 적용하지 않는다. DB를 새로 만든 경우와, 1번과 2번 사이에 꺼진 경우가 모두 이 한 규칙으로 처리된다. 끝 줄이 잘려 있거나 읽지 못하는 줄은 건너뛰고 로그에 남긴다.

한계: `userData`가 통째로 사라지면 값도 사라진다. 이 위험은 파일 기록 PR로 해결한다.

## 6. 값 넣기 규칙

대상은 사용자가 고른 파일이고, 기준 사진 자신은 빠진다. 사진 파일 경로는 화면에 주지 않는다.

**복사:** 기준 사진의 id만 기억한다. 값은 미리보기를 만들 때 main이 DB에서 읽는다. 복사한 값은 화면을 바꿔도 남고, 프로그램을 끄면 사라진다.

**붙여넣기 선택지**: 날짜, 시간, 위치 (기준 사진에 없는 값은 고를 수 없다. 시간은 날짜를 고를 때만 고를 수 있다)

| 고른 것 | 결과 |
|---|---|
| 날짜 + 시간 | 기준 시각부터 순서대로 +1초. 순서는 대상의 지금 찍은 시각, 파일 이름, id 순. 시간대는 기준 사진 값 |
| 날짜만 | 각 파일의 시각과 시간대를 유지. 시각이 없으면 12:00:00, 시간대는 기준 사진 값 |
| 위치 | 위도와 경도를 그대로 복사 |

**날짜 직접 넣기:** 달력과 시간(기본 12:00:00)을 입력한다. 시간대는 +09:00이고, 여러 장이면 같은 +1초 규칙을 쓴다. 연도는 1900년부터 올해까지만 받는다.

**이미 값이 있는 파일:** 덮어쓸 수 있다. 미리보기에 "원래 값이 있음"을 경고 노랑으로 따로 세어 보여 주고, 되돌리면 원래 값으로 돌아간다. 값이 같은 파일은 "그대로"로 세고 기록하지 않는다.

**안 되는 경우**
- 가져오기가 실행 중이면 미리보기, 넣기, 되돌리기를 거절한다 (파일이 옮겨지는 중이므로)
- 사라진 파일(`missing`)은 대상과 기준에서 뺀다
- 넣을 때 main이 미리보기를 다시 계산해서 저장한다. 화면이 보낸 값을 믿지 않는다
- 한 번에 최대 20,000장

## 7. 되돌리기

지금 백업 폴더의 마지막 묶음부터 차례로만 되돌린다. 같은 파일을 여러 묶음이 바꿨을 때 순서가 꼬이지 않게 하기 위해서다.

되돌리면 `edit_items.before_json`의 상태로 `manual_values`를 돌려놓고, `files`를 그 값으로 다시 계산한다 (날짜와 위치 각각, 직접 넣은 값이 있으면 그 값, 없으면 `orig_` 값). 이전 상태가 없었으면 `manual_values`의 그 줄을 지운다.

버튼은 두 곳에 있다. 넣은 직후의 알림 줄과, "내가 넣은 정보" 위쪽 줄이다. 문구는 "124장 위치 되돌리기"처럼 쓴다.

## 8. 화면

**왼쪽 메뉴:** "정보 없는 사진"을 켠다. 숫자는 날짜나 위치가 없는 파일 수이며 스크린샷의 위치 없음은 세지 않는다 (경고 노랑).

**정보 없는 사진 화면:** 도구줄의 탭이 "위치 없음 3,277", "날짜 없음 0", "내가 넣은 정보 0"으로 바뀐다. 검색과 정렬은 그대로 쓴다. 격자도 같다. 이 화면에서 스크린샷은 위치 없음 탭에 나오지 않는다. 탭이 비어 있으면 "날짜 없는 사진이 없어요"처럼 빈 화면 문구로 알려 준다.

**선택** (두 화면 공통)
- 클릭: 한 장 선택
- Ctrl+클릭: 더하거나 빼기
- Shift+클릭: 같은 날 안에서 범위 선택
- 날짜 칸의 "이 날 모두 선택", 도구줄의 "목록 전체 선택"
- 탭, 필터, 화면이 바뀌면 선택을 비운다. 값을 넣은 뒤에도 비운다

**우클릭 메뉴:** 선택에 없는 칸을 우클릭하면 그 칸만 선택한다.
- 날짜와 위치 복사 (한 장일 때만)
- N장에 붙여넣기 (복사한 값이 있을 때만)
- N장에 날짜 직접 넣기

**오른쪽 패널**
- 여러 장을 고르면 "N장 선택함"과 위 메뉴와 같은 버튼을 보여 준다 (우클릭을 모를 때를 위해)
- 복사한 값이 있으면 어느 파일의 값인지와 날짜, 위치를 작게 보여 준다
- 출처 문구에 "내가 넣은 값"을 더한다. 위치에도 출처를 보여 준다

**미리보기 창**
- 위쪽에 넣을 항목을 고르는 칸 (붙여넣기) 또는 날짜 입력 (직접 넣기)
- 바뀜, 그대로, 원래 값이 있음의 개수
- 파일별 전 → 후 목록 (앞 100줄만 그리고 "외 N장"으로 줄인다)
- 버튼은 결과를 말한다: "124장에 위치 넣기" / "그만두기"
- Esc로 닫는다

디자인은 `CLAUDE.md`의 색과 금지 사항을 따른다. 경고 노랑은 "정보 없음"에 관한 표시에만 쓰고, 색연필 빨강은 쓰지 않는다.

## 9. 화면과 main 사이

| 이름 | 하는 일 |
|---|---|
| `getState` (기존) | `noLocation`, `noInfo`, `manualCount`, `lastBatch`를 더함 |
| `listDays`, `listFiles` (기존) | filter에 `info`를 더함 (값: `noLocation`, `noDate`, `manual`) |
| `gallery:list-ids(filter)` | 조건에 맞는 id 전체 (목록 전체 선택용) |
| `gallery:get-copy-source(id)` | 복사할 값 요약 (파일 경로 없음) |
| `gallery:preview-edit(ids, edit)` | 미리보기 결과 |
| `gallery:apply-edit(ids, edit)` | 다시 계산해서 저장, 끝나면 `library-changed` 알림 |
| `gallery:undo-last()` | 마지막 묶음 되돌리기 |

`edit` 모양은 둘 중 하나다.
- `{ source: 'copy', sourceId, date, time, location }`
- `{ source: 'direct', date: 'YYYY-MM-DD', time: 'HH:MM:SS' }`

main에서 id 배열, 날짜 모양, 시각 모양, 선택지를 모두 검사한다.

## 10. 오류 처리와 로그

| 상황 | 동작 |
|---|---|
| 기록 파일을 못 씀 | 값을 넣지 않고 이유를 알림 |
| DB 저장 실패 | 전부 되돌리고 `void`를 적은 뒤 이유를 알림 |
| 기준 사진이 그 사이 사라짐 | 미리보기를 거절하고 다시 복사하라고 알림 |
| 폴더 연결 끊김 | 값 넣기와 되돌리기는 그대로 가능 (DB만 쓰므로) |
| 다시 읽는 중 | 넣을 수 있음. 저장 트랜잭션에서 다시 적용되므로 값이 사라지지 않음 |

로그: 넣기와 되돌리기마다 `lib/logger.js`로 묶음 번호, 개수, 파일별 전후 값을 남긴다. 복구했을 때는 복구한 묶음 수를 남긴다.

## 11. 점검 (`scripts/check-missing-info.js`, `check.js`의 목록에 추가)

샘플 복사본과 임시 `userData`로 실행한다. 실제 사진은 쓰지 않는다.

1. 넣기, 되돌리기 전후로 샘플 파일의 지문, 크기, 수정 시각이 같다
2. 버전 1 DB를 열면 파일 값이 그대로이고 버전 2가 된다
3. `noLocation` 필터가 스크린샷을 빼고, `manual` 필터가 직접 넣은 것만 고른다
4. +1초 규칙: 순서, 날짜 넘어감, 날짜만 넣을 때 시각 유지, 시각이 없으면 12:00:00
5. 선택지 처리: 기준에 없는 값 거절, 기준 사진 자신 제외, 사라진 파일 제외, 같은 값은 "그대로"
6. 파일을 바꿔 다시 읽어도 직접 넣은 값이 남고 `orig_`는 새 값이 된다

8. DB를 지우고 새로 만든 뒤 기록 파일로 복구하고 다시 읽으면 값이 같다 (되돌린 묶음은 되돌린 대로)
9. 기록 파일에 쓴 뒤 DB 저장 전에 꺼진 상황, 끝 줄이 잘린 기록 파일을 복구할 수 있다

11. 가져오기 중 거절, 이상한 id와 날짜 거절, 응답에 파일 경로가 없음

## 12. 안전 규칙 확인

- 이 PR에는 삭제, 이동, 이름 바꾸기, exiftool 쓰기를 넣지 않는다. 쓰는 곳은 `userData` 안의 DB, 기록 파일, 로그뿐이다. 검증 에이전트가 이 점을 확인한다.
- 넣기 전에 미리보기를 거치고, 모든 작업을 로그와 기록 파일에 남긴다.
- 가져오기가 항상 우선이고, 기존 가져오기 동작은 바꾸지 않는다. 기존 점검이 모두 통과해야 한다.
- 영상 촬영일 규칙은 읽기 코드를 바꾸지 않으므로 그대로 지켜진다.
