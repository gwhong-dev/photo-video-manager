# 가져오기 전 거르기 + 가져올 때 태그 한 번에 설계

> 2026-11-18 사용자 요청 · 방식 결정: "1번 (휴지통으로 거르기)"
> 등급 L (`gallery-main.js` 버리기 연결 · `main.js` 가져오기 흐름 · 태그 저장)

## 1. 왜
- 7만 장 첫 정리는 끝났어요. 앞으로는 **수백~수천 장을 한 번씩** 가져와요 (예: 어제 찍은 200여 장, `I:\무제`, 한 행사 "에버랜드에서 찍은 삼성라이온즈")
- 사용자가 바라는 순서:
  1. 가져올 폴더를 고른다 → **그 폴더 안에서 중복 · 비슷한 사진을 먼저 거른다**
  2. 다 거르면 백업 폴더로 가져온다 (이름 바꾸기 · 확장자 변환 · 날짜 폴더 분류, 지금 기능 그대로)
  3. 가져올 때 **폴더 전체에 이름표 하나를 한 번에** 붙인다
- 지금은 비슷한 사진 화면이 백업 폴더(라이브러리) 안의 사진만 봐요 → 다 가져온 뒤에야 비교할 수 있고, 새 사진 200장이 6만 장 사이에 섞여요

## 2. 목표 · 안 할 것 · 실패로 볼 것
- 목표
  - 가져오기 화면에서 고른 폴더로 **지금의 비슷한 사진 화면**(썸네일 · 지문 · 흐림 · AI 비교 · 추천 1장 남김 · 묶음별 옮기기)을 그대로 연다
  - 거기서 버린 사진은 **가져올 폴더 쪽 휴지통**으로 (휴지통이 없는 드라이브면 `가져올 폴더\_정리완료원본`). 폴더에서 빠지니 다음 미리보기에서 자연히 빠져요
  - 미리보기 화면에 **"가져온 사진에 태그 붙이기"** 칸. 기본값 = 가져올 폴더 이름. 실행이 끝난 사진에 그 태그를 붙여요 (되돌리기 가능)
- 안 할 것
  - 계획에서만 빼기(2번 방식) · 고르는 화면 새로 만들기
  - 라이브러리의 옛 사진과 새 사진을 "비슷한 사진"으로 비교하기 (같은 파일은 지금처럼 미리보기에서 "중복"으로 빠짐)
  - 앨범 만들기 (앱의 앨범은 iCloud 정보라 읽기 전용 → 태그로)
  - 사진 파일에 태그 쓰기 (지금처럼 DB · 기록 파일에만)
- 실패로 볼 것 (동작해도)
  - 거르기 중에 **백업 폴더(라이브러리) 사진이 옮겨지거나**, 라이브러리의 태그 · 날짜 · 모두 남기기 기억이 바뀌는 것
  - 거르기 화면을 닫은 뒤에도 갤러리가 가져올 폴더를 보고 있는 것 (설정의 백업 폴더가 바뀐 것처럼 보이는 것)
  - 태그가 이번 작업과 상관없는 사진에 붙는 것, 되돌리기로 안 지워지는 것
  - 영구 삭제

## 3. 방식 (고른 것과 버린 것)
| 방식 | 내용 | 결과 |
|---|---|---|
| **1. 휴지통으로 거르기 (고름)** | 갤러리 엔진을 가져올 폴더에 잠깐 붙여 비슷한 사진 화면을 그대로 씀. 버린 사진은 가져올 폴더 쪽 휴지통 | 이미 검증한 화면 · 버리기 · 로그를 다시 씀. 작고 안전 |
| 2. 계획에서만 빼기 | 미리보기 계획에 "건너뛰기" 표시, 원본은 그대로 | 고르는 화면 새로, 원본 정리 때 건너뛴 사진 규칙(`lib/cleaner.js`)도 새로 → 몇 배 큼 |
| (버림) 가져온 뒤 "이번 사진만" 보기 | 다 가져온 뒤 비슷한 사진 화면을 이번 작업 사진으로 거름 | 버릴 사진이 라이브러리에 잠깐 들어감. 사용자가 "먼저 거르고 옮기기"를 원함 |

태그 vs 폴더 이름(하위 폴더로 옮기기): 날짜 폴더 분류와 부딪혀서 태그로 (Claude 판단).

## 4. 동작

### 4-1. 거르기 모드 (갤러리 쪽)
- `gallery-main.js` 의 `rootNow()` 는 지금 `settings.backupRoot` 만 봐요. 여기에 **거르기 폴더**(메모리에만 두는 값, 설정 파일에 안 씀)를 더해요
  - 거르기 중이면 `rootNow()` = 거르기 폴더, 아니면 지금처럼 백업 폴더
  - 거르기 폴더는 `main.js` 가 가져오기 화면에서 고른 `source` 로만 정해요. 화면이 경로를 보내지 않아요 (지금 규칙처럼 경로는 main 이 설정에서)
- DB 는 이미 `root` 열쇠로 폴더를 나눠요 → 가져올 폴더 사진은 `root = 가져올 폴더` 로 따로 들어가고 라이브러리 줄과 섞이지 않아요
- 거르기 모드에서 쓸 수 있는 것: **비슷한 사진 화면**과 **사진 보기(갤러리 격자) + 바로 지우기**(흐린 한 장 등)
  - 막는 것: 날짜 · 위치 넣기, 태그 붙이기 · 태그 화면, 날짜없음 채우기, 지도, 정리 기록 화면. 가져올 폴더의 경로에 붙은 값은 가져오면 경로가 바뀌어 사라지기 때문 (Claude 판단)
  - "모두 남기기" 기억(`similar-keeps.json`)은 경로로 적혀 라이브러리와 안 섞여요. 그대로 써도 됨
- 화면 맨 위에 거르기 띠: `가져오기 전 거르기: 무제 (사진 212장)` + 버튼 `거르기 끝내고 가져오기로` (버튼은 결과를 말함)
  - 띠의 폴더 표시는 폴더 이름만 (화면에 전체 경로를 보내지 않는 지금 규칙)
- 버리기 · 바로 지우기는 지금 함수(`lib/similar-discard.js` `discardFiles`)를 그대로 쓰고 `root` 만 거르기 폴더로 → 거르기 폴더 **밖**의 파일은 지금처럼 옮기지 않음(실패). 휴지통 없는 드라이브면 `거르기 폴더\_정리완료원본` (가져오기 미리보기가 이미 이 폴더를 건너뜀, `lib/planner.js` `MOVED_DIR`)
- 끝내기(버튼, 또는 가져오기 화면으로 돌아갈 때 · 앱을 끌 때): 거르기 폴더 값을 비우고 지문 · AI 계산을 멈춤 → 갤러리는 다시 백업 폴더
  - DB 에 남은 거르기 폴더 줄: 끝낼 때 지우지 않고 둬요(같은 폴더를 다시 거르면 썸네일 · 지문을 다시 안 만들어도 됨). 가져온 뒤 원본이 사라지면 다음 거르기 때 "사라짐"으로 맞춰져요 (Claude 판단, 줄이 쌓이는 문제는 나중에 할 일)

### 4-2. 가져오기 화면 (`index.html` · `main.js`)
- 가져올 폴더를 고르면 폴더 줄 옆에 버튼 `비슷한 사진 먼저 거르기`
  - 누르면: 실행 중 · 미리보기 중이면 막음(지금 화면 바꾸기 규칙과 같음) → main 이 거르기 폴더 = `source` 로 정함 → 갤러리 화면을 비슷한 사진 탭으로 열고 폴더 읽기 시작
  - 가져올 폴더와 백업 폴더가 같거나 안쪽이면 지금 `validateFolders` 처럼 거부
- 갤러리에서 `거르기 끝내고 가져오기로` → 거르기 모드 끝 → 가져오기 화면으로. 상태 줄: `거르기에서 N장을 휴지통으로 옮겼어요. 미리보기를 눌러 남은 사진을 확인해 주세요`
- 진행 중인 작업이 있어도 거르기는 할 수 있어요 (원본을 옮기는 건 거르기 폴더 안뿐). 단 진행 중인 작업의 가져올 폴더와 같은 폴더면 "진행 중인 작업을 먼저 끝내 주세요"로 막아요 (작업 목록에 있는 원본이 사라지면 실패가 생김)

### 4-3. 가져올 때 태그 한 번에
- 미리보기 결과 아래 칸: `☑ 가져온 사진에 태그 붙이기 [에버랜드에서 찍은 삼성라이온즈]` — 기본 켬, 기본 이름 = 가져올 폴더 이름(태그 이름 규칙 `cleanTagName` 으로 다듬음, 안 맞으면 빈칸 + 끔)
- 실행(`start-job`) 때 태그 이름을 작업에 같이 적어요 (작업 파일에 `tag` 칸 하나 더함. 없는 옛 작업은 태그 없음 → 옛 작업 기록과 호환)
- 붙이는 때: 회차(`run-batch`)가 끝나고 갤러리가 새 파일을 다 읽은 뒤
  - 대상: 이번 작업에서 `done` 인 파일의 결과 파일(`finalPath`) + `dup`(이미 라이브러리에 있던 같은 사진)의 남길 파일. 백업 폴더 안의 것만
  - 지금 태그 붙이기와 같은 길(`tagAdd` 묶음 1개 · 기록 파일 `manual-edits.jsonl` 먼저 · 되돌리기 줄)로 → 갤러리 되돌리기 바(UndoBar)로 한 번에 뗄 수 있음
  - 태그가 없으면 태그 정의(`tag_names`)에도 만들어요
  - 이미 붙은 사진은 그대로 (숫자 키 규칙과 같음). 회차가 여러 번이면 회차마다 그 회차에 끝난 사진만
  - 붙이기가 실패해도 가져오기 결과는 그대로, 로그 + 상태 줄 한 줄 (`태그를 붙이지 못했어요. 갤러리에서 직접 붙여 주세요`)

## 5. 점검 (`scripts/check*.js`, 샘플 복사본으로)
- 화면 없이: 거르기 폴더를 정하면 `rootNow` 가 바뀌고 끝내면 돌아옴 / 거르기 중 막힌 기능이 거부됨 / 거르기 중 버리기는 거르기 폴더 안만 옮김, 라이브러리 파일 그대로 / 진행 중인 작업과 같은 폴더면 거부 / 태그: done · dup 의 백업 쪽 파일에만, 되돌리면 모두 떨어짐, 옛 작업(태그 칸 없음)은 안 붙임, 이름 규칙에 안 맞는 폴더 이름
- 진짜 앱: 가져오기 화면 → 거르기 버튼 → 비슷한 사진 탭에 샘플 묶음 → 1장 버림 → 돌아오기 → 미리보기 개수 1 줄어듦 → 실행 → 갤러리에 태그 붙음 · 되돌리기 → 설정 파일 백업 폴더 그대로

## 5-1. 코드와 맞춰 본 것 (2026-11-18 Claude 검토, 검토 에이전트는 사용 한도로 못 돌림)
- 옛 썸네일 정리(`pruneOrphans`)는 켠 뒤 처음 끝까지 읽은 폴더에서 한 번 돌아요 (`gallery-main.js` `runScan`). 그 첫 폴더가 거르기 폴더면 안 되게, **거르기 폴더 읽기에서는 정리하지 않음**
- 회차 끝(`onBatchDone`)은 `rootNow()` 를 다시 읽어요. 거르기 모드가 켜진 채 가져오기를 시작하면 백업 폴더 대신 거르기 폴더를 읽게 됨 → **가져오기(미리보기 · 실행 · 원본 정리)를 시작할 때 거르기 모드가 켜져 있으면 먼저 끔**
- 태그는 `computeTagPlan(root, ids, …)` 처럼 사진 번호로 계산해요 → 회차 끝 다시 읽기(`runScan(root, { changed: true })`)가 **끝난 뒤** 결과 파일 경로를 번호로 바꿔 붙임 (읽기 결과가 `done` 이 아니면 다음 회차 끝이나 다음 켤 때 다시 시도하지 않고 상태 줄 안내만, Claude 판단)
- 라이브 포토 짝 영상은 버리기 때 지금처럼 같이 옮겨짐 (`lib/similar-discard.js` pairs) → 가져올 폴더에서도 짝이 같이 빠짐
- `insideRoot` 가 거르기 폴더 밖 · `_정리완료원본` 안을 이미 막아요 → 라이브러리 사진은 거르기 중에 옮길 수 없음

## 6. 만드는 사람에게 맡김
- 거르기 띠 · 버튼의 정확한 위치와 모양 (화면 디자인 규칙: 버튼 문구는 결과, 가운뎃점으로 잇지 않기)
- 태그 붙이기를 갤러리 쪽 함수로 둘지 공용 함수로 뺄지
- 거르기 모드에서 막은 기능의 메뉴를 숨길지 흐리게 할지
