# 갤러리 설계 (단계 2: DB + 썸네일 + 갤러리 화면)

> 작성일: 2026-11-01 / 등급: L (DB 구조) / 브랜치: `feature/gallery`
> 화면 참고: Figma v0.2 "갤러리" (`CLAUDE.md`의 링크). 색과 글꼴은 `CLAUDE.md` "화면 디자인"을 따른다.

## 1. 목표와 성공 기준

정리가 끝난 백업 폴더의 사진과 영상을 날짜별 격자로 보고, 찾고, 정보를 확인한다. 뒤 단계(정보 없음, 비슷한 사진, 태그, 지도)가 쓸 DB의 토대가 된다.

성공 기준
- 6만 개에서 스크롤이 끊기지 않는다
- 프로그램을 다시 켜면 바뀐 파일만 읽는다
- 갤러리를 쓰는 동안 사진 폴더의 파일은 하나도 바뀌지 않는다
- 외장하드를 빼도 목록과 썸네일은 그대로 보이고, DB의 파일 정보가 사라지지 않는다

## 2. 범위

이번에 만드는 것
- 백업 폴더 읽기 (DB 저장, 진행 표시, 바뀐 파일만 다시 읽기)
- 사진과 영상 썸네일
- 날짜별 격자 (가상 스크롤), 영상 길이 표시
- 탭 (전체, 사진, 영상, 스크린샷), 정렬 (찍은 날짜 최신순, 오래된순)
- 검색 (파일 이름, 태그, 날짜)
- 왼쪽 메뉴, 앨범 태그 목록 (누르면 그 태그만 보기)
- 오른쪽 정보 패널 (읽기 전용)

이번에 만들지 않는 것
- 태그 추가, 날짜와 위치 복사 및 붙여넣기 (단계 5, 3): 버튼을 그리지 않는다
- 지도, 패널의 작은 지도 (단계 6): 패널에는 좌표 숫자만 표시한다
- 장소 이름 ("수원시 팔달구"): 날짜 옆에는 날짜, 요일, 장수만 표시한다
- "라이브" 표시, 전체 화면 보기, 영상 재생
- 가져오기 화면을 React로 옮기기, exe 패키징

왼쪽 메뉴에서 아직 없는 화면(정보 없는 사진, 비슷한 사진, 태그, 지도, 정리)은 흐리게 표시하고 누를 수 없게 한다. 숫자는 있는 것만 표시한다: 갤러리(전체 개수), 정보 없는 사진(날짜 없는 개수, 경고 노랑), 태그(태그 개수).

## 3. 먼저 할 일: Electron 업그레이드

`feature/electron-upgrade` 브랜치의 작은 PR로 38에서 최신 버전으로 올린 뒤 `feature/gallery`를 시작한다. CI가 `feature/**`에서만 돌기 때문에 브랜치 이름도 이 규칙을 따른다. 기존 `npm run check`와 앱 실행이 그대로 통과하면 끝이다.

## 4. 구조

```
main.js ── gallery IPC와 pvm:// 프로토콜 연결
  lib/db.js       DB 열기, 구조 관리, 조회와 저장 (SQL은 이 파일에만)
  lib/library.js  폴더 읽기, 정보 읽기, 바뀐 파일 판단
  lib/thumbs.js   썸네일 만들기, 대기열
  lib/search.js   검색어 해석 (날짜 모양 판단)
src/ ── React 화면 (Vite로 dist/renderer에 빌드)
  App, Sidebar, Toolbar, DayGrid, DetailPanel, ScanBanner, api.js
```

- `lib/`의 새 파일은 Electron을 직접 불러오지 않는다. `npm run check`가 일반 Node에서 그대로 실행하기 위해서다.
- 기존 코드 재사용: `lib/dates.js`의 `dateFromMeta`, `dateFromName`, `lib/planner.js`의 파일 찾기와 정보 읽기(`Keys:CreationDate`를 합치는 부분 포함). 두 곳에서 쓰도록 필요한 함수를 내보내되 동작은 바꾸지 않는다.

### 새 패키지

| 패키지 | 용도 |
|---|---|
| `react`, `react-dom` | 화면 |
| `vite`, `@vitejs/plugin-react` | 화면 빌드 (개발용) |
| `@tanstack/react-virtual` | 가상 스크롤 |
| `sharp` | 사진 썸네일 |
| `@fontsource/ibm-plex-sans-kr` | 글꼴 (인터넷 없이 동작) |

DB는 Electron과 Node에 들어 있는 `node:sqlite`를 쓴다. `better-sqlite3`는 Electron용과 점검용 빌드가 달라 번거롭다. 실험 기능이므로 SQL을 `lib/db.js` 한 곳에 모은다.

확인 상태: Electron 38의 Node 실행 모드에서 생성과 조회가 동작했다. 구현 첫 단계에서 실제 창 환경과 업그레이드한 버전으로 다시 확인하고, 실패하면 `better-sqlite3`로 바꾼다.

### 화면 전환

- 시작 화면은 갤러리다. 백업 폴더가 정해지지 않았으면 안내 문구와 "가져오기 화면 열기" 버튼을 보여 준다.
- 두 화면은 `open-screen` IPC로 `win.loadFile`을 바꿔 오간다. `index.html`에 갤러리로 가는 버튼을 하나 추가한다.
- `running`이 참이면 `open-screen`을 거부하고 이유를 표시한다. 진행 표시가 끊기지 않게 하기 위해서다.
- 이어할 작업이 있으면 왼쪽 메뉴 "가져오기"에 표시를 붙인다.
- `scripts/launch-check.js`를 쓰는 점검 1은 시작 화면이 바뀌므로 확인 문구를 갤러리 기준으로 고친다.

### 실행

- `npm start`는 `vite build && electron .`, `npm run check`는 점검 전에 빌드한다.
- `scripts/start.bat`: 더블클릭하면 `npm install` 후 `npm start`. `git pull` 뒤 쓴다.

## 5. DB

파일: `userData/library.db`. WAL 모드(읽기와 쓰기가 덜 막히는 방식). 구조 버전은 `PRAGMA user_version`으로 관리한다. 지금은 DB의 모든 값을 파일에서 다시 만들 수 있으므로, DB가 깨지면 이름을 바꿔 보관하고 새로 읽는다.

```sql
files (
  id INTEGER PRIMARY KEY,
  root TEXT NOT NULL,            -- 읽어 온 백업 폴더
  path TEXT NOT NULL UNIQUE,
  name TEXT NOT NULL,
  media_type TEXT NOT NULL,      -- photo | video
  size INTEGER NOT NULL,
  mtime_ms INTEGER NOT NULL,
  taken_at TEXT,                 -- 찍은 곳 현지 시각 2026-10-25T14:00:30
  taken_offset TEXT,             -- +09:00 (있을 때만)
  taken_day TEXT,                -- 2026-10-25, 날짜 없으면 NULL
  taken_at_source TEXT,          -- exif | filename (단계 3에서 manual 추가)
  lat REAL, lng REAL,
  location_source TEXT,          -- exif
  model TEXT,
  width INTEGER, height INTEGER,
  duration_sec REAL,
  thumb_state TEXT NOT NULL DEFAULT 'none', -- none | ready | failed
  missing INTEGER NOT NULL DEFAULT 0,       -- 폴더에서 사라짐 (화면에서 숨김)
  read_error TEXT
)
tags (id INTEGER PRIMARY KEY, name TEXT NOT NULL UNIQUE)
file_tags (file_id, tag_id, source TEXT NOT NULL, -- album | mediaType
           PRIMARY KEY (file_id, tag_id))
```

색인: `(root, missing, taken_day)`, `(root, missing, media_type, taken_day)`, `file_tags(tag_id)`.

태그 구분: `XMP-dc:Subject` 값이 `사진`, `비디오`, `스크린샷`이면 `mediaType`, 나머지는 `album`. 목록은 상수 하나로 두고, 실제 샘플에서 다른 값이 나오면 추가한다.

## 6. 폴더 읽기

1. 시점: 앱 시작, 가져오기 일괄 실행이 끝났을 때, "다시 읽기" 버튼, 백업 폴더가 바뀌었을 때.
2. 파일 찾기: 가져오기와 같은 규칙으로 찾는다. 후가공 폴더(`2025년도`), `_정리완료원본`, 숨김 파일, `.__tmp__` 파일을 제외한다.
3. DB와 비교: 경로, 크기, 수정 시각이 모두 같으면 건너뛴다. 단, 지난번에 읽기 실패한 파일(`read_error`)은 "다시 읽기" 버튼을 누르면 다시 읽는다.
4. 새 파일과 바뀐 파일만 exiftool로 500개씩 읽고 묶음마다 한 번에 저장한다. 저장할 때마다 화면을 새로 고치므로 읽은 사진부터 볼 수 있다.
5. 없어진 파일은 지우지 않고 `missing=1`로 표시한다. 다시 나타나면 되돌린다.

읽는 값: 기존 `META_TAGS`와 `Keys:CreationDate`에 `Duration#`, `ImageWidth`, `ImageHeight`를 더한다. 날짜 우선순위는 v1.1과 같다 (촬영 정보, 그다음 파일 이름). 파일 수정 날짜는 쓰지 않는다. 시간대 글자는 `taken_offset`에 따로 저장한다.

### 연결이 끊긴 경우의 안전 규칙

`missing` 표시는 폴더를 끝까지 읽었다고 확신할 때만 한다.

- 백업 폴더가 없으면 읽기를 하지 않고 "폴더 연결 안 됨"을 표시한다.
- 기존 찾기 함수는 못 읽은 폴더를 조용히 건너뛰므로, 못 읽은 폴더 목록을 알려 주는 선택 인자를 더한다. 못 읽은 폴더 안의 파일은 `missing`으로 만들지 않는다.
- 찾은 파일이 0개인데 DB에 파일이 있으면 연결 문제로 보고 아무것도 표시하지 않는다.
- 읽는 도중 오류가 나면 그 회차의 `missing` 표시는 건너뛴다.

### 가져오기와의 관계

exiftool은 한 개를 함께 쓰고 명령을 차례로 처리한다. 가져오기가 우선이다.

- `running`이 참이면 폴더 읽기와 백그라운드 썸네일은 묶음 사이에서 멈추고, 끝나면 이어 한다.
- 폴더 읽기는 `running`을 켜지 않는다. 가져오기 시작을 막지 않기 위해서다.

## 7. 썸네일

- 위치: `userData/thumbs/<앞 2글자>/<경로+크기+수정시각의 sha1>.webp`. 긴 변 320px. 사진 폴더에는 아무것도 만들지 않는다.
- 사진: `sharp`로 만들고 회전 정보를 반영한다. `sharp`가 못 여는 형식(bmp, dng 등)은 ImageMagick을 쓰고, 없으면 실패로 둔다.
- 영상: FFmpeg로 1초 지점의 한 장면을 뽑는다. 1초보다 짧으면 첫 장면을 쓴다.
- 대기열: 화면에 보이는 것을 먼저 만들고, 나머지는 쉬는 동안 동시에 몇 개씩 만든다. 스크롤로 지나간 요청은 뒤로 미룬다.
- 임시 이름으로 만든 뒤 이름을 바꿔, 중간에 꺼져도 깨진 썸네일이 남지 않게 한다.
- 실패하면 `thumb_state='failed'`로 두고 격자에 "미리보기 없음"을 표시한다. 파일이 바뀌거나 "다시 읽기"를 누르면 다시 시도한다.
- 오른쪽 패널 미리보기: 사진은 긴 변 1200px을 그때그때 만들어 보내고 저장하지 않는다. 영상은 썸네일을 쓴다.

### 이미지 전달 (`pvm://`)

- 화면은 파일 경로를 모른다. `pvm://thumb/<id>`, `pvm://preview/<id>`로 요청한다.
- `protocol.handle`은 id가 정수이고 DB에 있을 때만 응답하고, 그 외에는 404를 돌려준다.
- 경로를 받는 IPC는 만들지 않는다. CSP: `img-src 'self' pvm:`.

## 8. 조회와 화면

### IPC (`window.api.gallery`)

| 함수 | 결과 |
|---|---|
| `getState()` | 백업 폴더, 연결 여부, 전체 개수, 날짜 없는 개수, 태그 목록, 읽기 진행 상태 |
| `listDays(filter)` | `[{ day, count }]` |
| `listFiles(day, filter)` | 그 날의 파일 목록 (id, 이름, 종류, 영상 길이, 썸네일 상태) |
| `getFile(id)` | 패널에 보일 전체 정보와 태그 |
| `rescan()`, `openScreen(name)` | 다시 읽기, 화면 전환 |
| `onScanProgress(cb)`, `onLibraryChanged(cb)` | 진행 상황, 목록 갱신 알림 |

`filter`: `{ tab, sort, query, tag }`. 날짜 없는 파일은 `day: null`로 항상 맨 끝에 온다.

### 격자

1. `listDays` 결과와 창 너비로 줄 목록을 계산한다: 줄 수 = 올림(장수 / 한 줄 칸 수).
2. 가상 스크롤은 화면 근처의 줄만 그린다.
3. 화면에 들어온 날의 파일만 `listFiles`로 가져와 기억한다. 아직 없으면 빈 칸을 그린다.

왼쪽 날짜 칸은 Figma처럼 그 날 묶음의 맨 위에 "10.28", 요일, 장수를 쓴다. 해가 바뀌는 지점이 구분되도록 연도도 표시한다.

### 검색 (`lib/search.js`)

- 검색창 문구: "파일 이름, 태그, 날짜 검색". 입력 후 0.2초 뒤 실행한다.
- 공백으로 나눈 낱말이 모두 맞는 파일을 찾는다.
- 낱말이 날짜 모양이면 날짜로도 찾는다: `2026`, `2026-10`, `2026.10.28`, `2026년 10월`, `10.28`(연도 상관없이). 그 낱말은 파일 이름과 태그에서도 찾는다 (예: `2026년도_44주차`).
- `LIKE`를 쓴다. FTS5 trigram은 세 글자 미만을 못 찾아 두 글자 한글 태그에 맞지 않는다.
- `%`, `_`는 글자 그대로 찾도록 처리하고, 값은 항상 SQL 매개변수로 넘긴다.
- 결과가 없으면 "찾는 사진이 없어요"와 검색어 지우기 버튼을 보여 준다.

### 오른쪽 패널

선택한 파일의 미리보기, 파일 이름, 찍은 시각과 출처("사진 파일에서 읽음" 또는 "파일 이름에서 읽음"), 좌표, 기기, 가로세로 크기, 용량, 태그를 보여 준다. 없는 값은 "정보 없음"(경고 노랑)으로 표시한다. 아무것도 고르지 않았으면 안내 문구를 보여 준다.

### 디자인

`CLAUDE.md` "화면 디자인"의 색과 금지 사항을 따른다. 색연필 빨강은 이 화면에서 쓰지 않는다. Figma 연결 도구가 호출 한도에 걸렸으므로 정확한 간격은 구현 때 다시 확인하고, 안 되면 내장 브라우저 화면을 기준으로 맞춘다.

## 9. 오류 처리

| 상황 | 동작 |
|---|---|
| 백업 폴더 없음 (USB 뺌) | "폴더 연결 안 됨" 표시, 목록 유지, 읽기 안 함 |
| 백업 폴더가 정해지지 않음 | 안내 문구와 가져오기 화면 버튼 |
| exiftool 없음 | 읽기 안 함, 도구 안내 표시, 이미 저장된 목록은 표시 |
| FFmpeg 없음 | 영상은 "미리보기 없음", 나머지 동작 |
| 파일 하나 읽기 실패 | `read_error`에 기록, 파일 이름에 날짜가 있으면 그 날짜를 쓰고 없으면 날짜 없음, 계속 진행 |
| 읽는 중 앱 종료 | 저장된 묶음은 유지, 다음에 켜면 남은 것부터 |
| DB 열기 실패 | 파일 이름을 바꿔 보관하고 새로 읽기, 로그와 화면에 알림 |

로그: 읽기 시작과 끝(개수, 걸린 시간), 읽기 실패, 썸네일 실패 합계를 `lib/logger.js`로 남긴다.

## 10. 점검 (`scripts/check.js`)

샘플 복사본으로 실행한다. 실제 사진은 쓰지 않는다.

1. 읽기 전후로 샘플 파일의 지문, 크기, 수정 시각이 같다
2. 영상 날짜를 `Keys:CreationDate`에서 먼저 읽고, 출처를 맞게 저장한다
3. 태그를 `album`과 `mediaType`으로 나눈다
4. 다시 읽으면 exiftool 호출 없이 끝나고, 파일 하나를 바꾸면 그 파일만 읽는다
5. 파일 삭제 후 `missing`, 복원 후 되돌림
6. 폴더가 없거나 비었거나 일부를 못 읽으면 `missing`이 늘지 않는다
7. 사진과 영상 썸네일이 만들어지고, 깨진 파일은 `failed`가 되며 전체 작업은 멈추지 않는다
8. 검색: 파일 이름, 두 글자 태그, 날짜 모양, `%` 글자, 낱말 여러 개
9. `pvm://` 처리 함수가 없는 id, 숫자 아닌 값, 경로 모양의 값을 거부한다
10. 가짜 6만 건에서 `listDays`, `listFiles`, 검색 시간 측정 (목표 0.2초, 1초를 넘으면 실패)
11. 앱을 띄워 갤러리 화면 글자와 오류 없음을 확인한다 (기존 점검 1 수정)

CI로 확인할 수 없는 것은 이 PC에서 확인한다: 실제 스크롤 체감, 복사본 폴더 첫 읽기 시간, USB를 뺐을 때 표시. 측정 시간으로 6만 개 첫 읽기 시간을 계산해 PR에 적는다.

## 11. 안전 규칙 확인

- 갤러리 코드에는 삭제, 이동, 이름 바꾸기, exiftool 쓰기를 넣지 않는다. 쓰는 곳은 `userData` 안의 DB와 썸네일뿐이다. 검증 에이전트가 이 점을 확인한다.
- 영상 촬영일 규칙을 지킨다.
- 가져오기가 항상 우선이고, 기존 가져오기 동작은 바꾸지 않는다. 기존 점검이 모두 통과해야 한다.
