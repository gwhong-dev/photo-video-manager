# 지도에서 위치 고르기 설계 (단계 3의 셋째 PR)

> 작성일: 2026-11-02 / 등급: M (기능 추가, DB 구조 변경 없음, 사진 파일에 쓰지 않음) / 브랜치: `feature/map-pick`
> 잇는 문서: `2026-11-01-missing-info-design.md`, `2026-11-02-location-suggest-design.md`. 값 넣기, 미리보기, 기록 파일, 되돌리기는 그 설계를 그대로 쓴다.
> 화면 참고: Figma v0.2. 이번 설계 때는 호출 한도로 보지 못했다. 구현 때 다시 보고, 못 보면 지금 화면과 프로젝트 지침의 색에 맞춘다.

## 1. 목표와 성공 기준

위치 제안으로 채울 수 없는 약 1,223장과 건너뛴 사진에, 사용자가 지도에서 고른 위치를 넣는다. 이 앱이 처음으로 인터넷에 연결되는 기능이므로, 무엇이 언제 어디로 나가는지를 좁게 정한다.

성공 기준
- 사진을 고른 뒤 장소를 검색하거나 지도를 눌러 핀을 놓고, 미리보기를 거쳐 넣을 수 있다
- 넣은 값은 복사 붙여넣기와 똑같이 저장되고 되돌릴 수 있다 (출처 `manual`)
- 지도 창을 열기 전에는 인터넷에 한 번도 연결하지 않는다
- 인터넷이 끊겨도 앱의 다른 기능은 그대로이고, 지도 창에 이유가 한 줄로 보인다
- 이 기능을 쓰는 동안 사진 폴더의 파일은 하나도 바뀌지 않는다

## 2. 범위

이번에 만드는 것
- 사진 여러 장에 위치 하나를 넣는 지도 창 (지도 클릭, 핀 끌기, 장소 검색)
- 메인 프로세스의 지도 그림 전달과 장소 검색 (`lib/map-net.js`)
- 기록 파일과 로그의 `via: map`

이번에 만들지 않는 것
- 지도에 사진 핀과 묶음 표시 (단계 6)
- 좌표를 장소 이름으로 바꾸기
- `[파일에도 기록]`
- 오프라인 지도 (지도 서버 정책이 금지)
- 자동완성 (검색 서버 정책이 금지)
- 카카오 검색 (Nominatim을 써 보고 부족할 때 별도 PR. 2026-11-04 사용자 결정: 지금은 추가하지 않음)

## 3. 사용 흐름

1. 갤러리나 `정보 없는 사진`에서 사진을 고르고, 우클릭 메뉴나 오른쪽 패널의 `N장 위치 지도에서 고르기`를 누른다. 위치 제안 탭은 읽기 전용이라 이 버튼이 없다
2. 미리보기 창(`EditDialog`)이 지도와 함께 열린다. 처음 위치는 이번 실행에서 마지막으로 고른 곳, 없으면 대한민국 전체다
3. 지도를 누르면 핀이 놓이고, 핀은 끌어서 옮길 수 있다. 검색 결과를 누르면 그곳으로 이동해 핀이 놓인다
4. 핀이 바뀔 때마다 지금 쓰는 미리보기 목록이 다시 만들어진다. 이미 위치가 있는 사진은 지금처럼 `원래 값이 있음`으로 경고한다
5. `N장에 위치 넣기`를 누르면 창이 닫히고 되돌리기 줄이 나온다

검색은 Enter나 검색 버튼으로만 보낸다. 결과는 최대 5개를 주소와 함께 목록으로 보여 준다. **첫 결과에 핀을 자동으로 놓지 않는다.** 시험에서 `해운대해수욕장`의 첫 결과가 남극 부근 좌표였다.

검색창 아래에 항상 한 줄을 보여 준다: "검색어는 OpenStreetMap 서버로 보내요. 이름이나 전화번호 같은 개인정보는 적지 마세요."

## 4. 인터넷 연결 규칙

### 4-1. 구조

화면은 지금처럼 인터넷에 직접 나가지 않는다. `src/index.html`의 보안 설정(CSP)은 바꾸지 않는다. 메인 프로세스의 `lib/map-net.js`만 나간다.

```
지도 그림: 화면 → pvm://tile/<z>/<x>/<y> → gallery-main.js → map-net → 지도 서버
장소 검색: 화면 → IPC gallery:search-place → gallery-main.js → map-net → 검색 서버
```

`lib/map-net.js`는 Electron을 부르지 않고, `fetch`를 받아서 쓴다. 그래서 점검을 일반 Node와 가짜 응답으로 돌릴 수 있다 (`lib/` 규칙).

### 4-2. 나가는 것과 나가지 않는 것

- 나감: 보고 있는 지역의 지도 번호, 입력한 검색어, IP 주소, 앱 이름표(User-Agent)
- 나가지 않음: 사진, 파일 이름, 폴더 경로, 사진에 든 좌표 목록
- 로그에 남기지 않음: 검색어 (실패 로그에는 HTTP 상태와 오류 코드만)

### 4-3. 연결하는 곳

| 쓰임 | 기본 주소 | 설정 키 |
|---|---|---|
| 지도 그림 | `https://tile.openstreetmap.org/{z}/{x}/{y}.png` | `mapTileUrl` |
| 장소 검색 | `https://nominatim.openstreetmap.org/search` | `placeSearchUrl` |

- 검색 서버 정책은 요청을 받으면 앱을 다시 설치하지 않고 서비스를 바꿀 수 있어야 한다고 요구한다. 그래서 주소를 `settings.json`에서 바꿀 수 있게 한다. 화면에 설정 칸은 만들지 않는다
- 설정 값이 비어 있으면 기본 주소를 쓴다. `https://`가 아니거나, 지도 주소에 `{z}`, `{x}`, `{y}`가 없으면 기본 주소를 쓰고 오류 로그에 키 이름만 남긴다
- 다른 주소로 넘기는 응답(리다이렉트)은 따라가지 않고 실패로 본다

### 4-4. 서버 정책에 맞추는 일

공통
- User-Agent: `photo-video-manager/<package.json 버전> (https://github.com/gwhong-dev/photo-video-manager)`. 브라우저인 척하지 않는다
- 실패하면 자동으로 다시 시도하지 않는다. 사용자가 다시 움직이거나 다시 눌렀을 때만 보낸다

지도 그림
- `z`는 0~19, `x`와 `y`는 0 이상 `2^z` 미만의 정수만 받는다. 나머지는 나가기 전에 404
- 화면에 보이는 영역만 받는다. 미리 내려받거나 넓은 지역을 훑지 않는다
- 서버의 캐시 지시를 따른다. `net.fetch`가 쓰는 Chromium HTTP 캐시에 맡기고, 구현 첫 단계에서 가짜 서버(`max-age`, `ETag`)로 실제로 지켜지는지 확인한다. 지켜지지 않으면 `userData/map-tiles`에 7일 캐시를 직접 만든다
- 지도 오른쪽 아래에 `© OpenStreetMap 기여자`를 항상 보여 준다
- 서버가 429나 403을 주면 60초 동안 지도 서버에 보내지 않는다 (지도를 끌어도 더 나가지 않게)

장소 검색
- 요청 사이를 최소 1초 둔다. 그 안에 다시 누르면 기다렸다가 보낸다. 동시에 하나만 보낸다
- 같은 검색어는 이번 실행 동안 저장해 둔 결과를 쓴다 (최대 100개, 메모리에만). 검색 요청은 디스크 캐시에 남기지 않는다 (`cache: 'no-store'`)
- 사용자가 누를 때만 보낸다. 사진 목록을 돌며 자동으로 찾지 않는다
- 요청: `format=jsonv2`, `limit=5`, `accept-language=ko`, `q=<검색어>`. 나라는 제한하지 않는다 (해외 사진)
- 검색어는 앞뒤 공백을 빼고 1~200자만 받는다
- 응답은 `{ name, lat, lng }`만 남긴다. 좌표가 숫자가 아니거나 범위를 벗어난 줄은 버린다

제한시간은 지도 그림 10초, 검색 15초다. 지도 그림 응답은 `image/png`이고 2MB 이하일 때만 넘긴다.

### 4-5. 링크

Leaflet의 기본 출처 표시는 끈다 (창 안의 링크를 누르면 앱 창이 그 사이트로 넘어가기 때문). 출처는 직접 그린 버튼으로 두고, 누르면 고정 주소 `https://www.openstreetmap.org/copyright`를 기본 브라우저로 연다. 화면이 주소를 보내지 않는 IPC `gallery:open-map-credit` 하나만 만든다. `shell.openExternal`은 `main.js`에서 받는다.

## 5. 값 넣기

새 요청 모양: `{ source: 'pin', lat, lng }`

- `lib/manual-edit.js` `normalizeRequest`: `checkLocation`으로 검사하고 소수점 6자리로 줄인 뒤 `{ kind: 'location', date: null, location, sourceId: null }`을 돌려준다
- `gallery-main.js` `apply-edit`: `via`는 `map`, `sourcePath`는 `null`. 지금 `via === 'direct'`로 판단하는 부분을 `edit.source !== 'copy'`로 바꾼다. 로그 제목은 `지도로 넣기`
- `computePlan`, `planEdit`, `toPreview`, DB 저장, 기록 파일, 되돌리기는 그대로 쓴다. DB 구조는 그대로다
- 넣은 값은 위치 제안의 근거 사진이 되지 않는다 (지금 규칙: 출처 `manual`은 근거에서 뺌)
- 화면이 보낸 경도가 범위를 벗어나면 거절되므로, 화면은 Leaflet 좌표를 `wrap()`해서 보낸다

## 6. 화면

- `EditDialog`에 `mode="map"`을 더한다. 위쪽 칸만 달라지고, 미리보기 요청, 요청 번호, 넣기, 오류 표시는 같은 코드를 쓴다. 핀이 없으면 `지도에서 위치를 골라 주세요`
- 새 컴포넌트 `src/components/MapPicker.jsx`: 지도, 검색, 결과 목록, 출처, 오류 줄. props는 `value`, `onChange`
- Leaflet은 1.9 대로 고정한다 (단계 6의 묶음 플러그인이 1.x용). 번들에 포함한다
- 핀은 이미지 없이 CSS로 그린다. 색은 글자색 `#F1EEE6`과 배경색 `#3B3A37`. 빨강과 노랑은 쓰지 않는다
- 창의 Tab 순환, Esc 닫기는 지금 규칙을 따른다
- 끊겼을 때 안내
  - 지도 그림 실패: `지도를 불러오지 못했어요. 인터넷 연결을 확인해 주세요.`
  - 검색 실패: `장소를 찾지 못했어요. 잠시 뒤 다시 눌러 주세요.`
  - 검색 결과 없음: `찾은 곳이 없어요. 근처 지역을 검색한 뒤 지도에서 눌러 주세요.`
  - 이미 놓은 핀과 미리보기, 넣기는 그대로 쓸 수 있다
  - 지도 그림이 하나도 안 떴거나 실패 문장이 보이는 동안 지도 클릭은 막고 `지도가 보일 때 눌러 주세요. 검색 결과는 지금도 고를 수 있어요.`를 보여 준다. 검색 결과는 주소가 있어서 그대로 고를 수 있다

## 8. 점검

`scripts/check-map-pick.js` (진짜 인터넷에 나가지 않음)
- 잘못된 `z`, `x`, `y`는 `fetch`를 부르지 않고 404
- 나가는 주소는 정해진 두 곳뿐이고 User-Agent가 앱 이름이다
- `https://`가 아닌 설정은 기본 주소로 돌아가고 값은 로그에 남지 않는다
- 리다이렉트, 시간 초과, 429, 잘못된 JSON, 형식 틀린 줄을 처리한다. 다시 시도하지 않는다
- 검색 간격이 1초 이상이고, 같은 검색어는 다시 보내지 않고, 검색어가 로그에 남지 않는다
- `{ source: 'pin' }`의 좌표 검사와 반올림, `0`도 값
- 넣기 뒤 기록 파일에 `via: map`, `sourcePath: null`이 남고, 되돌리기와 켤 때 복구가 된다
- `src/index.html` CSP에 `http`가 없다 (화면이 직접 나가지 않음)

실제 확인 (이 PC, 복사본 목록)
- 앱을 켜고 지도 창을 열기 전까지 지도와 검색 서버로 요청이 없다
- 지도, 핀, 검색, 미리보기, 넣기, 되돌리기, 끄고 다시 켜기
- 인터넷을 끊은 상태의 안내
- 사진 폴더 차이 0

M 등급이라 독립 검증을 1번 받는다.

## 9. 위험과 한계

- 공개 지도와 검색 서버는 보장이 없고 예고 없이 막힐 수 있다. 막히면 지도 기능만 안 되고 다른 기능은 그대로다. 설정으로 주소를 바꿀 수 있다
- 검색 서버 정책은 사용자 수가 적당한 앱만 허용한다. exe를 널리 배포하게 되면 서비스를 다시 정한다
- 작은 가게는 검색에 안 나올 수 있다 (`스타벅스 강남역` 0건). 근처를 찾아 지도에서 누르면 된다
- 보고 있는 지역은 지도 서버가 알 수 있다
