# 정리 화면 설계 (읽기만)

> 2026-11-09 사용자 승인: 가 = 정리 기록 보기 (나: 이 화면에서 원본 정리, 다: 안 만듦 중에서)
> 아무것도 옮기거나 지우지 않아요. 원본 정리는 지금처럼 가져오기 화면의 🧹 배너에서 해요

## 1. 화면
- 왼쪽 메뉴 "정리"를 켜고 가운데에 `CleanView`, 오른쪽에 `CleanPanel`
- 위: 정리한 원본을 옮겨 둔 폴더 (`_정리완료원본`)
  - 가져올 폴더 · 백업 폴더마다: 있는지, 파일 수, 크기, "○○의 _정리완료원본 열기" 버튼
  - 안내: 휴지통이 없는 드라이브는 지우지 않고 이 폴더로 옮김, 휴지통으로 보낸 파일은 Windows 휴지통에서 되살릴 수 있음
- 아래: 정리 기록 표 (언제, 무엇, 휴지통, 옮김, 실패, 끝까지 기록되지 않음). 줄을 누르면 오른쪽에 그때의 파일 이름과 간 곳 (휴지통, _정리완료원본, 실패와 이유)
- 끝 줄이 없는 기록은 "도중에 꺼졌을 수 있어요, 마지막 파일을 확인해 주세요"

## 2. 데이터 (`lib/clean-history.js`)
- 로그 폴더의 `clean_*.txt` (원본 정리), `similar-discard_*.txt` (비슷한 사진 버리기)만 읽어요. 최근 100개, 기록 하나에 파일 300줄까지
- 줄 규칙: "예정", "휴지통 실패 → 이동"(안내) 줄은 세지 않고, "실패" · "휴지통" · "이동" 줄을 세요. "짝 영상" 표시, "# 끝" 줄로 끝까지 기록됐는지
- 화면에는 파일 이름만 보내요 (경로 없음). `_정리완료원본` 폴더 크기는 파일 20만 개에서 멈추고 "이상"으로
- 폴더 열기: 화면은 `source` / `backup` 만 보내고, 경로는 main 이 설정에서 정해 `shell.openPath` 로 열어요. 없는 폴더는 열지 않아요

## 3. 점검
- 45 (화면 없이): 가짜 로그 3개 + 세지 않을 로그로 기록 읽기, `_정리완료원본` 크기, IPC (경로 없음, 정한 경로만 열기, 이상한 값 · 없는 폴더 · 열기 실패), 읽기만 (코드에 옮기기 · 지우기 · 쓰기 없음)
- 46 (진짜 앱): 정리 메뉴 → 기록 3줄, 폴더 줄, 기록을 누르면 파일과 간 곳, 끝 줄 없는 기록 안내, 화면에 경로 없음
