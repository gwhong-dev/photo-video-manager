### 0-1. C: 드라이브 휴지통 설정 확인 (검토 M1 ②)

원본 정리는 C: 같은 하드디스크에서 **휴지통**을 써요. (D:는 Windows가 USB로 인식해서 휴지통 대신 `_정리완료원본`으로 옮겨요 → 6번) 휴지통이 "바로 제거"로 설정돼 있으면 휴지통에 남지 않을 수 있어서 먼저 확인해요.

- [ ] **화면으로 확인**: 바탕화면 **휴지통 아이콘 우클릭 → 속성**
  - 위 목록에서 **로컬 디스크 (C:)** 를 고르고
  - [ ] "사용자 지정 크기"가 선택돼 있음 (최대 크기 **\_\_** MB 적어 두기)
  - [ ] "파일을 휴지통으로 이동하지 않고 삭제할 때 바로 제거"가 **체크 안 됨**
- [ ] (선택) **PowerShell로 확인** (읽기만 해요)

```powershell
Get-ChildItem 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Explorer\BitBucket\Volume' | ForEach-Object { Get-ItemProperty $_.PSPath } | Select-Object PSChildName, NukeOnDelete, MaxCapacity
```

- `NukeOnDelete`가 **1**이면 "바로 제거"(위험), **0**이거나 비어 있으면 휴지통 사용
- `PSChildName`의 `{…}` 번호가 어느 드라이브인지는 아래로 확인 (`DeviceID` 안의 같은 번호를 찾기)

```powershell
Get-CimInstance Win32_Volume | Select-Object Name, DeviceID
```

- [ ] 휴지통 최대 크기가 이번에 정리할 원본 용량보다 큰지 (작으면 먼저 넣은 원본부터 자동으로 비워져요)

## 8. 갤러리 (단계 2)

갤러리는 백업 폴더의 사진을 **읽기만** 해요. 지우거나 옮기거나 이름을 바꾸지 않아요. 만드는 것은 `%APPDATA%\photo-video-manager\` 안의 목록 파일(`library.db`), 썸네일 폴더(`thumbs`), 로그(`logs`)뿐이에요.

처음 켜면 백업 폴더를 통째로 읽고 썸네일을 만들어서 오래 걸려요. 6만 4천 개 기준 추정은 읽기 약 13분, 썸네일 약 77분, 썸네일 용량 약 0.6GB예요 (복사본 563개 측정에서 계산한 값, 느린 USB 드라이브는 더 걸릴 수 있어요).

## 9. 정보 없는 사진 (단계 3)

"정보 없는 사진" 화면에서 위치나 날짜가 없는 사진에 같은 날 다른 사진의 값을 복사해 붙여 넣어요. 넣은 값은 **앱의 목록(`library.db`)과 기록 파일(`manual-edits.jsonl`)에만** 저장돼요. 사진 파일에는 아무것도 쓰지 않아요 (사진에 쓰는 기능은 아직 없어요).

### 9-1. 복사본 목록으로 먼저 (Claude가 한 방법)

진짜 `%APPDATA%\photo-video-manager`는 건드리지 않고, 임시 폴더에 목록만 복사해서 앱을 띄워요.

- [ ] 진짜 `userData`에서 `settings.json`, `library.db`, `library.db-wal`, `library.db-shm`, `thumbs` 폴더를 임시 폴더(`%TEMP%\pvm-check-...`)로 **복사만** 함 (원본은 읽기만. `logs`는 복사하지 않음)
- [ ] 앱을 환경변수 `PVM_USER_DATA=<그 임시 폴더>`로 띄움 (이 값이 없으면 진짜 폴더를 써요)
- [ ] 사진 폴더의 경로, 크기, 수정 시각을 앱을 켜기 전과 끈 뒤에 각각 적어 비교함 (파일 내용은 읽지 않음)
- [ ] 끝나면 임시 폴더만 지움

### 9-2. 진짜 목록으로 (사용자)

- [ ] **먼저**: 머지한 뒤에는 앱을 실행하는 폴더를 새 코드로 갱신하고(`git pull`), **옛 빌드는 켜지 않아요**. 이번 버전에서 `library.db` 구조가 처음 바뀌었어요(버전 2). 옛 빌드가 이 목록을 열면 깨진 파일로 보고 이름을 바꿔 새로 만들어서, 폴더를 다시 읽는 데 읽기 약 18분 + 썸네일 약 54분이 걸려요 (직접 넣은 값은 기록 파일에서 되살아나요)
- [ ] **어디서**: 앱 → 왼쪽 메뉴 `갤러리` → 위쪽 검색창에 날짜를 입력해서 그날 사진을 찾음 (예: `2026-10-28`)
- [ ] **무엇을**: 위치가 있는 사진 한 장을 누르고 오른쪽 패널의 `날짜와 위치 복사` → 메뉴 `정보 없는 사진` (검색어는 그대로 남음) → `이 날 모두 선택` → 패널의 `N장에 붙여넣기` → 창에서 위치만 켜진 것을 확인하고 `N장에 위치 넣기`
- [ ] **성공 기준**: 넣은 직후 "N장에 위치를 넣었어요" 줄이 보이고, 탭 `위치 없음` 숫자가 N 줄고 `내가 넣은 정보`가 N 늘어남. 그 사진의 패널에 위치와 `내가 넣은 값`이 보임
- [ ] `N장 위치 되돌리기`를 누르면 숫자가 원래대로 돌아오고 패널의 위치가 다시 `정보 없음`
- [ ] 앱을 껐다 켜도 넣은 값이 남아 있고, 다시 읽기가 금방 끝남 (바뀐 파일만 읽어요)
- [ ] 조심: 하루에 장소가 여러 곳인 날(여행 등)에는 한 곳의 위치를 그날 전체에 붙이면 틀려요. 사진마다 확인하거나, 장소별로 나눠 고른 뒤에 붙여요

- [ ] **꼭 봐 주실 것**: `기기` 칸이 `정보 없음`인 사진의 제안이 실제로 맞는지 (오른쪽 패널에 보여요). 측정으로 검증하지 못한 부분이에요. 대략 몇 개 중 몇 개가 틀렸는지 알려 주세요
- [ ] **성공 기준**: 넣을 때마다 `남은 묶음` 숫자가 줄고 "N장에 위치를 넣었어요" 줄이 보임. `N장 위치 되돌리기`로 돌아옴. 앱을 껐다 켜도 건너뛴 사진이 다시 나오지 않음

### 9-4. 지도에서 위치 고르기 (사용자)

이 기능은 앱이 처음으로 인터넷 서버에 연결하는 곳이에요. 지도 창을 열기 전에는 지도 서버와 검색 서버(OpenStreetMap, 무료 공개 지도)에 연결하지 않아요. 지도 창을 열면 그 서버에 다음이 나가요: 지금 보는 지역의 지도 번호, 입력한 검색어, 내 IP 주소, 앱 이름표(`photo-video-manager/버전`). 사진, 파일 이름, 폴더 경로는 나가지 않아요. 검색창에는 이름이나 전화번호 같은 개인정보를 적지 마세요.

참고: 이 PC에서 확인한 내용이에요. 창을 열기 전에도 Chromium(앱 안에 든 브라우저 엔진)의 네트워크 기록에 두 가지가 보여요. 하나는 프록시(인터넷 연결을 대신 전해 주는 중간 서버) 설정을 찾으려고 `wpad`라는 이름을 물어본 것인데, 이 PC에서는 이름을 찾지 못해 실패했어요. 이 이름을 찾을 수 있는 네트워크(회사나 학교 등)에서는 Chromium이 그 컴퓨터에서 설정을 받아 올 수 있어요. 다른 하나는 `[2001:4860:4860::8888]:443`으로 가는 IPv6 UDP 연결 시도 2번인데, 이 PC에서는 "갈 곳 없음"으로 실패했고 데이터를 보낸 흔적은 기록에 보이지 않아요. 왜 시도하는지는 기록만으로 알 수 없어요. 이전에는 Chromium이 한국어 맞춤법 사전을 구글 서버에서 내려받는 일도 있었는데, 맞춤법 검사를 꺼서 없앴어요.

- [ ] **먼저**: 앱을 실행하는 폴더를 새 코드로 갱신(`git pull`)하고 옛 빌드는 켜지 않아요 (9-2의 먼저와 같아요)
- [ ] **어디서**: 앱 → 왼쪽 메뉴 `정보 없는 사진` → 탭 `위치 없음` → 사진 한 장을 누름 → 오른쪽 패널의 `1장 위치 지도에서 고르기` (사진을 우클릭해도 같은 메뉴가 있어요)
- [ ] **무엇을**: 창이 열리면 검색창에 `경복궁`을 키보드로 직접 입력하고 Enter. 결과 목록에서 첫 줄(`경복궁, ...`, 주소 부분은 서버에 따라 달라요)을 누름
- [ ] **성공 기준**: 처음에는 지도에 핀이 없고 아래 버튼이 `지도에서 위치를 골라 주세요`로 꺼져 있음. 결과를 누르면 지도가 경복궁으로 가서 핀이 놓이고, 미리보기에 `정보 없음 → 37.57975, 126.97668`이 보이고, 버튼이 `1장에 위치 넣기`로 바뀜
- [ ] **넣기와 되돌리기**: `1장에 위치 넣기`를 누름 → "1장에 위치를 넣었어요" 줄이 보이고 `위치 없음` 숫자가 1 줄고 `내가 넣은 정보`가 1 늘어남. `1장 위치 되돌리기`를 누르면 숫자가 원래대로 돌아옴. 앱을 껐다 켜도 넣은 값이 남아 있음
- [ ] **한글 입력 중 Enter**: `경복궁`을 칠 때 마지막 글자가 아직 조합 중일 때(밑줄이 보일 때) 바로 Enter를 누름. 검색이 한 번만 나가고 글자가 깨지거나 두 번 검색되지 않으면 성공 (Claude는 진짜 한글 입력기를 못 써서 확인하지 못했어요)
- [ ] **출처 버튼**: 지도 오른쪽 아래 `© OpenStreetMap 기여자`를 누름. 기본 브라우저에서 OpenStreetMap 저작권 안내 쪽이 열리고, 앱 창은 그대로 지도 창이면 성공 (Claude는 사용자 브라우저가 열려서 누르지 않았어요)
- [ ] **인터넷이 끊겼을 때**: 와이파이를 끄거나 랜선을 뽑고 지도 창을 엶. 지도 칸에 "지도를 불러오지 못했어요. 인터넷 연결을 확인해 주세요."가 보이고, 검색하면 "장소를 찾지 못했어요. 잠시 뒤 다시 눌러 주세요."가 보이면 성공. 지도를 누르면 핀 대신 "지도가 보일 때 눌러 주세요. 검색 결과는 지금도 고를 수 있어요."가 보여요. 이때도 앱의 다른 기능은 그대로 쓸 수 있어야 하고, 연결을 되살린 뒤 창을 다시 열면 지도가 떠야 해요 (Claude는 진짜로 끊어 보지 않았어요)
- [ ] **지도를 눌러 핀 놓기와 끌기**: 지도가 다 보일 때 지도를 눌러 핀을 놓고, 핀을 끌어 옆으로 옮김. 미리보기의 좌표가 옮긴 자리로 바뀌면 성공 (핀 끌기는 Claude가 가짜 지도에서만 해 봤어요)
- [ ] **한 곳을 못 찾을 때**: 작은 가게는 검색에 안 나올 수 있어요. "찾은 곳이 없어요. 근처 지역을 검색한 뒤 지도에서 눌러 주세요."가 보이면 근처 지역(예: `강남역`)을 검색하고 지도를 눌러 핀을 놓으면 돼요
- [ ] 조심: 검색 결과의 첫 줄이 틀린 곳일 수 있어요 (예전 시험에서 `해운대해수욕장`의 첫 결과가 남극 부근이었어요). 그래서 앱이 핀을 자동으로 놓지 않아요. 결과를 눌러 지도에서 맞는 곳인지 보고 넣어요. 지도를 쉴 새 없이 움직이거나 검색을 연달아 누르지 말아요 (무료 서버를 함께 쓰는 거예요)
