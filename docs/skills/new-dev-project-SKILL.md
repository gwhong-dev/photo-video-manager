# 새 개발 프로젝트 셋팅

> 2026-11-23 고친 판: 셋팅 PR 에 **토큰 설정(`.claude/settings.json`) · CLAUDE.md "토큰 규칙"** 을 더했다. 근거는 photo-video-manager `docs/개발-토큰-점검-가이드.md` (비용의 70% 이상이 긴 대화를 다시 읽는 값).

목표: 사용자가 "새 프로젝트 셋팅" 한 마디와 입력 3개만 주면, 나머지는 한 번에 끝낸다. 중간에 "다음 단계 완료하면 말해주세요"로 끊지 않는다.

## 1. 받을 것 (메시지에 없는 것만 한 번에 묻기)
1. 프로젝트 이름 (예: 사진관리프로그램)
2. GitHub 저장소 `owner/repo`
3. 한 줄 목표
4. 서버 배포가 있는지 (있음 → 완료 기준 "머지 + 배포 · 헬스 UP" / 없음 → "머지 + 실행 확인"). 모르면 "실행 확인"으로 두고 답에 한 줄로 알린다.

## 2. 만들 것 (이 순서로, 한 답변 안에서)

### ① 통합문서 (Claude Docs)
이름 "<이름> 통합문서", 탭 구조(탭은 왼쪽 목록):
- **해야할일** (a0): 날짜 · 작성자 줄 → "끝난 일은 작업기록 탭으로 옮겨요. 저장소: <링크>" → `## 진행 중`("지금 진행 중인 분기는 없어요.") → `## 사용자가 할 일` 표(할 일 | 어디서 · 어떻게 | 관련) → `## 개발 (Claude)` 표(할 일 | 등급 | 메모) → `## 보류 · 결정 필요` → `## 목표`(한 줄 목표)
- **작업기록** (a1) > 오늘 탭 "MM/DD (요일)": 표(PR | 한 일 | 결과), 첫 행 = "— | 통합문서 생성 | 탭: 해야할일 · 작업기록 · 자료"
- **자료** (a2): 하위 탭 언급 목록
  - 개발 문서: 표(문서 | 내용), 첫 행 = 저장소 링크 | 원본 저장소
  - 화면 시안: 표(시안 | 내용), "— | 아직 없음"
- 사용자가 해야할일 표에 "셋팅 마무리 (프로젝트 · 지침 · Code PR)" 한 행을 넣는다.

### ② 프로젝트 지침 (코드블록으로 답변에)
```
<이름> 프로젝트 지침 (대답은 한글로) — v1 (<YYYY-MM-DD>)
1. 이 채팅의 역할
기획 · 문서 정리 · 디자인 시안 전용. 코드 작업 · 기능 초안 · 버그는 Claude 데스크톱 앱 Code 탭에서 함
코드 관련 요청이 오면 "Code 탭에서 그대로 말하세요" 한 줄로 안내
개발 규칙의 유일한 원본 = 저장소 <owner/repo> 의 CLAUDE.md. 이 지침과 다르면 CLAUDE.md 를 따름
2. 자료를 읽는 곳 (GitHub 연동)
저장소의 PROGRESS.md · PROGRESS-LOG.md · docs/ (있는 것 기준)
3. 목표
<한 줄 목표>
4. 안전
비밀값(비밀번호, API 키, 토큰)은 절대 출력하지 않음 (키 이름만)
개인정보가 보이는 캡처는 공개 문서에 넣지 않음
5. 안내 방식
답변은 항상 한국어. 짧고 핵심 먼저, 표 · 굵게 · 이모지로 한눈에, 처음 나온 영어 용어는 한글 풀이
사용자에게 시킬 때는 단계별로: 어디서 열고 → 무엇을 입력하고 → 어떤 결과면 성공인지 + "되어 있나요? → 안 되어 있으면 이렇게"
에러는 "원인 한 줄 → 해결 → 이유" 순서
채팅 하나 = 주제 하나. 대화가 길어지면 결정을 정리해 두고 새 채팅에서 이어감 (긴 대화는 말할 때마다 전체를 다시 읽어 비용이 큼)
6. 통합문서 트리 (자동 등록)
- 통합문서: <통합문서 링크>
- 아티팩트(Docs · Design 등)나 파일을 만들거나 새 버전을 만들면, 그 답변 안에서 바로 project-artifact-tree 스킬로 트리에 링크 등록. 채팅 보관 때까지 미루지 않음
- 채팅을 마칠 때 이번 채팅에서 만든 것과 트리를 대조해 빠진 것 등록
- "트리 등록"이라고 하면 PROGRESS-LOG.md 의 "트리 등록 필요" 항목도 반영
7. 작업 자동 정리 (채팅 · Code 공통, 요청 없이)
- 채팅에서 결정 · 정리 · 문서 작업 하나를 끝내면 통합문서 "작업기록 > MM/DD (요일)" 탭에 한 줄 추가 (한 일 | 결과). 탭이 없으면 만듦
- 개발 시작 · 완료 때 해야할일 행을 '진행 중' → '작업기록' 으로 옮김
- 채팅을 시작하면 먼저 저장소 PROGRESS-LOG.md 의 "트리 등록 필요 · 트리 반영 필요" 항목을 확인해 통합문서에 반영 (Code 가 남긴 완료 내용 옮기기)
- 절차는 project-artifact-tree 스킬을 따름
```

### ③ 저장소 셋팅 PR (채팅이 직접 올림 — 기본)
Code 에 파일을 첨부하는 단계를 없애기 위해, 채팅이 저장소에 PR 을 직접 올린다.
1. add_repo 로 `<owner/repo>` 를 access "push" 로 연결하고, 안내된 경로에 클론한다.
2. 저장소가 비어 있으면(커밋 0개) PR 을 만들 수 없다 → 사용자에게 "GitHub 저장소 설정에서 README 를 하나 만들어 주세요" 한 줄 안내하고 대체 방법으로 간다.
3. 브랜치 `chore/project-setup` 에서 아래를 만든다 (내용은 아래 "대체" 템플릿의 2~5단계와 같음):
   - `.claude/skills/project-artifact-tree/SKILL.md` — 계정 스킬 그대로 복사
   - `.claude/settings.json` — 토큰 설정 (대체 템플릿 3단계. 파일이 있으면 `env` 키만 더하고 다른 키는 그대로)
   - `CLAUDE.md` — "통합문서 트리 등록" · "토큰 규칙" 섹션 (있으면 맨 아래에 추가, 같은 제목이 있으면 건너뜀)
   - `PROGRESS-LOG.md` · `PROGRESS.md` — 없을 때만
4. 커밋 → push → PR 생성. 제목 "프로젝트 셋팅: 통합문서 트리 스킬 · 토큰 설정 · CLAUDE.md · 작업 기록". 본문 끝에는 세션이 정한 attribution 줄.
5. 셋팅 PR 은 바로 머지한다 (사용자가 미리 정한 규칙: 셋팅 파일만 담긴 PR 은 확인 없이 머지). CI 가 있으면 통과를 기다린 뒤 머지하고, 실패 · 충돌 · 브랜치 보호로 막히면 머지하지 말고 PR 링크와 원인 한 줄을 준다. 셋팅 파일 말고 다른 변경이 섞인 PR 은 머지하지 않는다. 이미 있던 `.claude/settings.json` 의 다른 키(권한 · 훅 · 플러그인)를 바꿔야 하는 경우도 머지하지 말고 PR 링크만 준다.
6. add_repo 가 권한을 거부하거나 push · PR 이 실패하면 한 번만 원인을 말하고 아래 대체 방법으로 간다. 같은 동작을 반복 시도하지 않는다.

#### 대체: PR 을 못 올릴 때만 — 저장소용 파일 2개 만들어 보내기
- `SKILL.md`: 계정 스킬 project-artifact-tree 의 SKILL.md 를 그대로 복사. 찾기: `find ~/.claude/skills -path '*project-artifact-tree/SKILL.md'`. 못 찾으면 사용자에게 그 계정 스킬을 저장했는지 묻는다.
- `code-setup-instructions.md`: 아래 템플릿을 채운다.

````
# <repo> — Code 세션 초기 셋팅 (<YYYY-MM-DD>)

이 파일과 함께 첨부한 SKILL.md 로 아래 1~7을 순서대로 해줘. 각 단계가 끝나면 결과를 한 줄로 알려줘.

## 1. 저장소 최신화
- 작업 폴더가 <owner/repo> 인지 확인 (git remote -v). 아니면 멈추고 알려줘.
- git pull. 이미 .claude/skills/project-artifact-tree/SKILL.md 가 있으면 첨부 파일과 내용만 비교.

## 2. 스킬 파일 넣기
- 첨부한 SKILL.md 를 .claude/skills/project-artifact-tree/SKILL.md 로 저장.

## 3. 토큰 설정 (.claude/settings.json)
- 없으면 새로 만든다. 있으면 env 키만 더하고 다른 키(권한 · 훅 · 플러그인)는 건드리지 않는다.
```json
{ "env": { "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "200000" } }
```
- 뜻: 대화가 20만 토큰을 넘으면 자동 요약 (Claude Code 공식 설정, 10만 이상 토큰 수). 폴더를 신뢰한 뒤 적용된다.
- 이 프로젝트에서 안 쓰는 플러그인이 분명하면 같은 파일 enabledPlugins 에 false 로 적는다. 모르면 넣지 않는다.

## 4. CLAUDE.md 에 섹션 2개 추가 (없으면 파일 새로)
## 통합문서 트리 등록
- 통합문서: <통합문서 링크>
- 아티팩트(Docs · Design · HTML)를 만들면 작업 끝에 project-artifact-tree 스킬을 쓴다.
- 할 일 상태 옮기기(요청 없이 자동): 개발 시작 때 해야할일 행 → '진행 중', <완료 기준> 때 '진행 중' 행 → '작업기록 > MM/DD (요일)'.
- 작업이 끝날 때마다 PROGRESS-LOG.md 에 한 줄(날짜 | 작업 | 문제 | 해결 | 결과 | 비고)을 남기고, 통합문서도 갱신한다. 통합문서를 못 열면 비고에 "트리 반영 필요"를 적는다 (다음 채팅이 시작할 때 옮김).
- Claude Docs 를 열 수 없으면 PROGRESS-LOG.md 비고에 "트리 등록 필요: 제목 · 링크 · 탭"을 남기고 사용자에게 알린다.
- 스킬 원본은 계정 스킬 project-artifact-tree. 이 저장소 파일은 사본이다.

## 토큰 규칙
- 대화 길이 상한 20만 토큰: .claude/settings.json 의 CLAUDE_CODE_AUTO_COMPACT_WINDOW 로 자동 요약. 결정 · 다음 할 일은 요약 전에 PROGRESS.md 에 적는다
- 주제가 바뀌면 새 세션. 한 세션을 며칠씩 이어 쓰지 않는다. 메인 세션은 15만 토큰을 넘으면 하던 PR 끝에 새 세션으로 넘긴다
- 500줄 넘는 파일은 통째로 읽지 않는다: grep -n 으로 줄을 찾고 그 범위만. diff 는 --stat 먼저. 같은 범위 다시 읽기 금지 (자동 요약 뒤 · 파일 변경 뒤는 예외)
- 검증 에이전트를 쓰면: 중간 위험 변경은 바뀐 줄만 + sonnet, 큰 위험(삭제 · DB · 배포 · 규칙)은 전체 + opus. 분기 세션 모델은 start_session 의 model 에 직접 적는다
- 토큰이 많이 든다고 느끼면 짐작하지 말고 photo-video-manager 의 docs/개발-토큰-점검-가이드.md 스크립트로 집계부터 한다

## 5. 작업 기록 파일
- PROGRESS-LOG.md 가 없으면 만들고 표를 둔다: | 날짜 | 작업 | 문제 | 해결 | 결과 | 비고 |
- PROGRESS.md 가 없으면 만들고 맨 위에 "현재 상태 · 다음 할 일"을 둔다 (20줄 안팎 유지, 끝난 기록은 PROGRESS-LOG.md 로).

## 6. 브랜치 → PR
- 브랜치 chore/project-setup 에서 커밋, PR 제목 "프로젝트 셋팅: 통합문서 트리 스킬 · 토큰 설정 · CLAUDE.md · 작업 기록".
- 머지는 내가 확인한 뒤에.

## 7. 확인
- "스킬 목록 보여줘" 기준으로 project-artifact-tree 가 보이는지. 안 보이면 원인 한 줄 → 해결 → 이유.
- 머지 뒤 새 세션에서 get_usage 로 자동 요약 기준이 20만 근처인지. 아니면 폴더 신뢰 여부를 확인하고 사용자에게 알린다.
````

## 3. 답변 끝: 사용자 체크리스트 (한 번에, 단계마다 성공 기준)
답변 맨 위 한 줄: "✅ 셋팅 끝 — 아래 1번(claude.ai 프로젝트 · 지침)만 하고 Code 에서 작업하세요." 사람이 할 일은 1번(프로젝트 · 지침)과 3번(Code 에서 git pull)뿐이다.
1. claude.ai → 프로젝트 → 새 프로젝트 "<이름>" → 자료 + → GitHub → 저장소 연결 → 지침 편집 → ② 붙여넣기. 성공: 그 프로젝트 새 채팅에서 "지침 요약해줘" → 6번까지 나옴. 저장소가 안 보이면 GitHub 연결의 저장소 접근 권한 확인.
(셋팅 PR 은 채팅이 이미 머지했다 — 답변에 "머지 완료 + 커밋 링크"로 알린다. 머지가 막혔을 때만: "PR 링크 열기 → 확인 → 머지"를 체크리스트에 넣는다.)
3. Code 탭에서 그 PC의 저장소 폴더(dev/<repo>)를 열고 "git pull 해줘". 성공: "스킬 목록 보여줘"에 project-artifact-tree 가 보이고, 폴더 신뢰를 물으면 "신뢰"를 누른다 (토큰 설정이 적용되는 조건). 다른 PC 도 git pull 만 하면 됨.
(대체 방법으로 갔을 때만 2번 대신: Code 에 파일 2개 첨부 → "code-setup-instructions.md 대로 1번부터 진행해줘" → PR 머지)

## 하지 않는 것
- 단계마다 멈춰서 "완료하면 말해주세요" 하지 않는다. 체크리스트는 한 번에 준다.
- 프로젝트마다 전용 트리 스킬을 새로 만들지 않는다. 공통 project-artifact-tree 하나를 쓴다.
- 비밀값을 지침 · 파일 · 통합문서에 넣지 않는다.
- 셋팅 파일 말고 다른 변경(기능 코드 등)을 셋팅 PR 에 넣거나 머지하지 않는다.
- 이미 있는 저장소의 `.claude/settings.json` 권한 · 훅을 셋팅 PR 에서 바꾸지 않는다.
