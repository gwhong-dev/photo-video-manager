# photo-video-manager 개발 개요 v3

> 정리일: 2026-10-29 / 대상: Windows PC 프로그램 (Electron + React)
> 이전 문서: `기능명세-가져오기-변환.md` (v1.1). 가져오기·변환·날짜 폴더 정리 상세 규칙은 그 문서를 따른다.

---

## 1. 왜 만드는가

- 아이폰 사진·영상이 정리 없이 약 6.4만 개 쌓임 (사진 50,738 / 영상 13,220)
- 비슷한 사진이 많고, 폰 화면에서는 정리가 힘듦
- PC의 큰 화면에서 **줄이고 → 분류하고 → 보관**하고 싶음
- 나중에는 정리된 데이터로 **SNS 자동 업로드 사이트**를 만들어 수익화를 시도할 계획

## 2. 역할 분담 (확정)

```
📱 아이폰 ──PhotoSync──▶ 💾 PC/외장하드 ──▶ 🖥️ 우리 프로그램 (정리 전담)
```

- **전송은 만들지 않는다.** PhotoSync 등 기존 앱에 맡긴다.
  - 이유: 전송 기능은 아이폰 앱(Swift, 개발자 계정, 심사)이 추가로 필요하고 경쟁 앱이 이미 완성도가 높음
- 우리 프로그램은 **"폴더에 쌓인 사진·영상을 정리"**하는 데 집중한다.
- 맥미니(Mac)는 프로그램 실행에 필요하지 않다.

## 3. 자동으로 정보를 읽는 출처 (확정)

| 출처 | 읽는 곳 | 비고 |
|---|---|---|
| PhotoSync | 파일 안 정보 + XMP `dc:subject` 태그 | 2026-10-29 실제 파일로 검증 완료 |
| 구글 포토 (테이크아웃) | 파일 안 정보 + 사진별 JSON | 형식은 샘플로 확인 필요 |
| 아이클라우드 데이터 사본 (privacy.apple.com) | 파일 안 정보 + 앨범 CSV / 상세 정보 CSV | 형식은 샘플로 확인 필요 |

- 위 출처 외의 파일(카톡 등)에서 **정보를 추정하지 않는다.**
- 정보가 없으면 **"⚠️ 정리할 정보 없음"** 목록으로 모아서 알려준다.
  ```
  ⚠️ 날짜 정보 없음: 37개   [보기]
  ⚠️ 위치 정보 없음: 152개  [보기]
  ```

### 3-1. PhotoSync 파일 검증 결과 (2026-10-29)

| 정보 | 사진 | 영상 |
|---|---|---|
| 촬영 시각 (+09:00 시간대 포함) | ✅ | ✅ |
| 위치 (GPS) | ✅ (스크린샷·외부 이미지는 원래 없음) | ✅ (HEVC→H264 변환 파일은 ❌) |
| 기종 | ✅ | ✅ |
| 앨범 이름 → 태그 | ✅ 예: `2026년도_43주차`, `수원시` | ✅ |
| 미디어 종류 → 태그 | ✅ `사진`, `스크린샷` | ✅ `비디오` |

### 3-2. 코드에서 꼭 지킬 읽기 규칙

- **영상 날짜는 `com.apple.quicktime.creationdate`(exiftool: `Keys:CreationDate`)를 우선으로 읽는다.**
  - `creation_time`(QuickTime CreateDate)에는 **전송한 시각(UTC)**이 들어 있어서, 잘못 읽으면 전부 오늘 날짜로 분류된다.
- 태그는 XMP `dc:subject`(exiftool: `XMP-dc:Subject`)에서 읽는다.
  - 앨범 이름과 미디어 종류(`사진`, `비디오`, `스크린샷` 등)가 섞여 있으므로 둘을 구분해서 저장한다.
- 같은 시각 + `_1`, `_2` 이름 = PhotoSync가 이름이 겹친 파일에 붙인 것 (예: 같은 사진에 필터만 다르게 적용한 3장)

### 3-3. PhotoSync 추천 설정

| 설정 | 값 | 이유 |
|---|---|---|
| HEIC → JPEG | 켜짐 | Windows 호환 |
| JPEG 품질 | 90~95% (선택) | 100%는 48MP 1장에 15~20MB |
| **HEVC → H264** | **끄기** | 변환하면 위치·기종 정보가 사라짐 (검증됨). MP4 변환은 우리 프로그램에서 재압축 없이 처리 |
| 덮어쓰기 허용 | 끄기 | 같은 초 촬영 파일 보호 |
| 사용자 앨범 이름을 태그로 | 켜짐 | 앨범 → 태그 |
| 미디어 유형을 태그로 | 켜짐 | |
| 위치 데이터 | 원본 | |

## 4. 기능 목록

| 단계 | 기능 | 상태 |
|---|---|---|
| 1 | 가져오기·변환·날짜 폴더 정리 (v1.1) | 구현됨, 실제 양 테스트 남음 |
| 2 | 라이브러리 기반: DB(SQLite) + 썸네일 + 갤러리 화면 | 새로 만들 것 (핵심 토대) |
| 3 | 정보 없음 목록 + 날짜·위치 추가 | 새로 만들 것 |
| 4 | 비슷한 사진 묶기 → 남길 것 선택 → 나머지 휴지통 | 새로 만들 것 |
| 5 | 태그 (자동: 앨범 태그 읽기 / 수동: 사람, 여행, 공연 등 여러 장 한 번에) | 새로 만들 것 |
| 6 | 지도 보기 (위치별 묶음, 아이폰 "장소"와 같은 방식) | 새로 만들 것 |
| 7 | Mac 버전 | 이후 |
| 8 | 모바일 / SNS 사이트 | 이후 |

순서 원칙: **먼저 줄이고(4) → 그다음 분류(5, 6)**

### 4-1. 날짜·위치 추가 기능 (단계 3)

**날짜**
- 직접 지정: 달력에서 날짜·시간 선택
- 기준 사진에서 복사 → 여러 장에 붙여넣기 (예: 같은 날 같은 곳에서 친구가 카톡으로 보낸 사진)
  - 옵션: 날짜만 / 날짜+시간
  - 여러 장에 같은 시각을 붙이면 순서대로 +1초씩 (정렬 꼬임 방지)

**위치**
- 지도에서 선택: 지도 클릭 또는 장소 검색 → 핀
- 기준 사진에서 복사 → 여러 장에 붙여넣기

**화면 흐름**
```
기준 사진 우클릭 → 📋 날짜·위치 복사
대상 사진 여러 장 선택 → 우클릭 → 📌 붙여넣기 (☑ 날짜 ☑ 시간 ☑ 위치)
→ 미리보기 (전 → 후) → [적용] / [취소]
```

**안전 규칙**
1. 미리보기 → 적용
2. 먼저 **DB에만 저장**하고, 원본 파일에는 **[파일에도 기록]** 버튼을 눌렀을 때만 exiftool로 기록
3. 직접 넣은 값은 출처 `manual`로 기록 → "내가 넣은 정보"만 따로 보기 가능
4. 변경 전 값은 로그에 남김 → 되돌리기 가능

```bash
# 날짜 기록 예시
exiftool -DateTimeOriginal="2026:10:25 14:00:30" -OffsetTimeOriginal="+09:00" 사진.jpg
# 위치 기록 예시
exiftool -GPSLatitude=37.2878 -GPSLatitudeRef=N -GPSLongitude=127.0134 -GPSLongitudeRef=E 사진.jpg
```

### 4-2. 비슷한 사진 묶기 (단계 4)

- 유료 클라우드 AI는 사용하지 않는다 (비용 + 개인정보 문제)
- ① 시간 묶기: N초 이내 연속 촬영 (시작값 3초, 설정 가능)
- ② 이미지 지문(pHash): 작게 줄여서 모양 비교, PC 안에서 처리
- ③ (선택, 나중에) 로컬 AI로 흔들림·눈 감음 점수
- 그룹마다 ⭐ 남길 것 선택 → 나머지는 **휴지통으로 이동** (영구 삭제 금지)
- 테스트 데이터: `2026-10-28_13-41-13_IMG_0031` / `_1` / `_2` (같은 사진, 필터 3종), `13-40-58` ~ `13-41-13` (몇 초 간격 연속 촬영)

## 5. DB 설계 원칙

값만 저장하지 말고 **출처와 신뢰도도 함께** 저장한다.

```js
{
  takenAt: "2026-10-25T14:00:30+09:00",
  takenAtSource: "exif",       // exif | sidecar | filename | manual
  location: { lat: 37.2878, lng: 127.0134 },
  locationSource: "exif",      // exif | sidecar | manual
  tags: [{ name: "수원시", source: "album" }, { name: "사진", source: "mediaType" }]
}
```
